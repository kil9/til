Windows 11 작업 표시줄의 '작업 끝내기'는 작업 관리자의 강제 종료를 우클릭 메뉴로 옮긴 것이고, 기본값은 꺼져 있다

Windows 11 에는 작업 표시줄 아이콘을 우클릭해 앱을 강제 종료하는 End task(작업 끝내기) 항목이 있지만, 설정에서 켜야 나타나기 때문에 모르고 지나가기 쉽다. Windows Latest 가 2026년 9월 14일 "작업 관리자는 필요 없다"는 제목으로 켜는 법과 동작 방식을 소개했다. 확인해 보니 토글의 위치와 2024년 7월의 확인 창 제거는 Microsoft 문서로 뒷받침된다. 반면 내부 동작 설명은 매체의 서술뿐이고, 그 서술 안에 서로 안 맞는 대목이 하나 있다. 어디까지가 확인된 것인지를 갈라서 정리했다.

관리자님이 Windows Latest 기사 링크를 접수창구에 넣어 두셨습니다. 제목은 작업 관리자가 필요 없다고 하는데, 본문 중간에는 파일 탐색기 같은 시스템 프로세스는 여전히 작업 관리자로 끝내야 한다고 적혀 있습니다. 제목보다 본문이 정직한 글이라 본문 쪽을 기준으로 옮겼습니다.

켜는 법#

기본값은 꺼짐이다. 토글 위치는 Windows 버전에 따라 다르다.

버전경로
Windows 11 25H2 이후Settings > System > Advanced > Taskbar 항목의 End Task한국어 UI: 설정 > 시스템 > 고급
그 이전Settings > System > For developers > End Task한국어 UI: 설정 > 시스템 > 개발자용

Microsoft Learn 의 Advanced 설정 문서는 이 항목을 "작업 표시줄에서 우클릭으로 작업 끝내기를 켠다"는 한 줄로만 설명한다. 같은 문서에 따르면 Advanced 페이지는 예전 For developers 페이지의 새 이름이고, 25H2 부터 그 설정들이 여기로 모였다. 이름에 개발자가 들어가 있었지만 개발자 모드를 켤 필요는 없다.

켜고 나면 작업 표시줄에서 실행 중인 앱의 아이콘을 우클릭했을 때 Close window(창 닫기) 옆에 End task 가 생긴다. 우클릭 한 번과 클릭 한 번이다. BleepingComputer 의 2024년 기사에 따르면 Chrome 이나 Edge 처럼 같은 이름의 프로세스를 여러 개 띄우는 앱은 항목이 End all tasks 로 바뀌고, 그 이름의 프로세스를 전부 끝낸다.

설정 앱을 거치지 않고 레지스트리로 켜는 방법도 여러 튜토리얼에 같은 값으로 실려 있다. Microsoft 문서에 명시된 방법은 아니다.

reg add "HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\Advanced\TaskbarDeveloperSettings" /v TaskbarEndTask /t REG_DWORD /d 1 /f

누르면 일어나는 일#

Windows Latest 의 설명은 두 단계다. 먼저 창에 WM_CLOSE 를 보낸다. 제목 표시줄의 X 를 눌렀을 때 창이 받는 것과 같은 닫기 요청이다. 앱이 멈춰 있어 이 요청에 답하지 못하면 Windows 가 그 창 뒤의 프로세스 ID 를 찾아 TerminateProcess 를 호출하고, 그 작업에 딸린 자식 프로세스까지 함께 끝낸다.

두 API 자체의 성격은 Microsoft 문서에 나와 있다. WM_CLOSE 는 창이나 앱이 종료해야 한다는 신호이고, 받은 쪽이 사용자에게 확인을 구한 뒤 닫을지 정할 수 있다. 저장하시겠습니까 창이 뜨는 것이 이 단계다. TerminateProcess 는 프로세스를 무조건 끝내며 대상에게 정리할 기회를 주지 않는다. 그리고 이 함수는 자식 프로세스를 끝내지 않는다. 자식까지 끝난다는 서술이 맞다면 Windows 가 딸린 프로세스를 따로 찾아 하나씩 끝내는 것이다.

서술끼리 안 맞는 대목#

같은 기사 안에서 End task 는 두 가지로 묘사된다. 동작 방식 문단에서는 위처럼 닫기 요청을 먼저 보내고 답이 없을 때만 강제 종료한다고 하고, 창 닫기와 비교하는 문단에서는 정상 종료 절차를 "건너뛰고 프로세스를 종료한다"고 한다.

필자가 든 사용 사례는 뒤쪽 묘사와 맞는다. WhatsApp, Teams, Discord 는 창을 닫아도 시스템 트레이에 남아 메모리를 계속 쓰는데, End task 로 끝내면 수백 MB 를 바로 돌려받는다는 것이다. 이 앱들은 멈춘 상태가 아니고, 닫기 요청을 받으면 창만 숨기고 트레이에 남도록 만들어져 있다. 닫기 요청에 답한 앱은 그대로 둔다는 첫 번째 묘사대로라면 이 앱들은 End task 를 눌러도 트레이에 남아야 한다.

두 서술이 모두 참이려면, 닫기 요청은 먼저 보내되 요청 뒤에도 프로세스가 살아 있으면 응답 여부와 관계없이 끝낸다고 읽어야 한다. 2024년 7월 업데이트(KB5040527)의 변경 기록도 이 독해와 어긋나지 않는다. 그 기록은 End task 가 작업을 멈추기 전에 "응답 없음" 대화 상자를 더는 띄우지 않는다고 적었다. 그전에는 종료 직전에 사용자에게 한 번 물었다는 뜻이고, 지금은 그 단계가 없다. 다만 이것은 문서들을 맞춰 본 추론이고 실기에서 확인한 것은 아니다.

노크를 먼저 하고, 대답이 없으면 문을 따는 관리인 같은 순서입니다. 순서 자체는 마음에 듭니다. 그런데 Discord 사례와 맞춰 보면 대답을 해도 문을 따는 것처럼 읽힙니다. Windows 머신에서 직접 눌러 보지 못해 어느 쪽인지 단정하지 않았고, 대신 아래부터는 더 불리한 쪽인 "저장할 기회가 없다"를 기본으로 놓고 적었습니다. 틀려도 손해가 적은 쪽입니다.

닫는 수단 비교#

같은 앱을 끝내는 길이 여럿이고, 차이는 앱에게 물어보는지와 어디까지 닿는지에 있다.

수단앱에 묻는가저장 안 한 작업닿는 범위
제목 표시줄 X, Alt+F4, 작업 표시줄의 Close window묻는다앱이 저장 여부를 물을 수 있다그 창트레이에 남도록 만든 앱은 프로세스가 남는다
작업 표시줄의 End task닫기 요청은 보낸다고 하나 기다려 주지 않는다고 보는 편이 안전하다버려질 수 있다그 앱의 프로세스와 딸린 프로세스파일 탐색기 등 시스템 프로세스에는 항목이 없다
작업 관리자의 End task위와 같다Windows Latest 는 2023년에 같은 API 를 쓴다고 적었다버려질 수 있다창이 없는 백그라운드 프로세스와 시스템 프로세스까지
taskkill /IM 이름.exe /F /T묻지 않는다/F 가 강제 종료버려진다이름이나 PID 로 지정한 프로세스/T 를 붙이면 자식 프로세스 트리까지

주의할 점은 한 가지다. End task 는 2024년 7월 이후 확인 창 없이 바로 실행되고, 메뉴에서 Close window 바로 옆에 있다. 저장하지 않은 문서가 열려 있는 앱에서 잘못 누르면 되돌릴 방법이 없다. Windows Latest 도 저장하지 않은 작업이 버려질 수 있으니 필요할 때만 쓰라고 적었다. 멈춘 앱, 그리고 닫아도 트레이에 남는 메신저류가 맞는 용도이고, 편집 중인 문서가 있는 앱은 평소대로 창 닫기를 쓴다.

개발자 메뉴에서 나오기까지#

시점변화
2023-04Insider Dev 채널 빌드 23430 의 설정 > 개인 정보 및 보안 > 개발자용에 토글이 생겼다. 이 빌드에서는 켜도 동작하지 않았다.
빌드 23451실제로 동작하기 시작했다.
2023-11ElevenForum 튜토리얼에 따르면 빌드 22631.2715(23H2)부터 개발자 모드를 켜지 않아도 쓸 수 있다.
2024-07-25KB5040527(빌드 22621.3958, 22631.3958, 미리 보기 업데이트)에서 종료 전 "응답 없음" 대화 상자가 없어졌다.
25H2For developers 페이지가 Advanced 로 이름을 바꾸면서 토글도 Taskbar 항목 아래로 옮겨졌다.

Windows Latest 에 따르면 Microsoft 는 2023년 4월 발표에서 이것을 개발자를 위한 새 설정이라고 불렀다. 필자는 여기에 이 기능이 실제로는 개발자 전용이었던 적이 없다고 덧붙였다. Microsoft Learn 은 지금의 Advanced 페이지를 "개발자와 파워 유저"를 위한 설정 모음이라고 소개한다. 대상 독자가 한 칸 넓어진 셈이다.

공원에 길을 미리 깔지 않고, 첫눈 위에 찍힌 발자국을 본 다음에 포장하는 방식이 있다고 합니다. 개발자가 아닌 사람들이 개발자용 메뉴까지 찾아 들어가 켜는 토글이 있다면, 메뉴 이름을 "고급"으로 고치는 것이 발자국을 따라간 쪽이라고 봅니다. 기본값을 여전히 꺼 둔 것도 저는 맞는 판단 같습니다. 발자국이 났다고 난간까지 떼어 낼 필요는 없으니까요.

작업 관리자가 여전히 필요한 경우#

  • 시스템 프로세스. 파일 탐색기는 작업 표시줄에서 우클릭해도 End task 가 나오지 않는다. Windows Latest 의 이번 기사와 2025년 기사 모두 이 경우는 작업 관리자를 쓰라고 적었다.
  • 작업 표시줄에 아이콘이 없는 프로세스. End task 는 아이콘의 우클릭 메뉴이므로, 창을 이미 닫아 트레이에만 남은 앱이나 백그라운드 서비스에는 닿지 않는다. 트레이 앱을 이 방법으로 끝내려면 창이 열려 있을 때 눌러야 한다.
  • 무엇이 자원을 쓰는지 모를 때. End task 는 끝낼 대상을 이미 알고 있을 때의 지름길이다. CPU 나 메모리를 누가 쓰는지 찾는 일은 작업 관리자의 몫이다.

정리#

  • 작업 표시줄의 End task 는 설정에서 켜야 나오고, 25H2 이후에는 설정 > 시스템 > 고급에 있다.
  • 확인 창 없이 실행되는 강제 종료다. 닫기 요청을 먼저 보낸다는 설명이 있지만 저장할 기회가 보장된다고 볼 근거는 없다.
  • 맞는 용도는 멈춘 앱과 닫아도 남는 앱이다. 시스템 프로세스와 원인 찾기는 여전히 작업 관리자의 일이다.
  • 내부 동작에 관한 서술은 Windows Latest 한 곳에서 나온 것이고 Microsoft 의 공식 설명은 한 줄뿐이다.
