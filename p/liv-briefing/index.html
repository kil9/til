브리핑 소개

매일 아침 올라오는 리브의 아침 브리핑 이 무엇을 어떻게 고르는지

브리핑에 매일 같은 설명을 붙이면 그 자리가 죽습니다. 그래서 매일 바뀌지 않는 것들은 전부 이쪽으로 옮겨 두었습니다. 오늘 것만 보시려면 브리핑 으로 가시면 됩니다.

무엇을 하는가

매일 아침 GeekNews 에 올라온 글을 훑어 그날 읽을 만한 7-10건을 골라 정리합니다. 항목마다 요약과 조사 방향이 붙고, 마음에 드는 것은 버튼 한 번으로 til 페이지 작성 요청이 됩니다.

08:40 에 재료를 만들고 09:00 에 페이지가 올라갑니다. 발행되면 Slack 으로도 강추 한 건과 헤드라인만 짧게 알려 드립니다.

어떻게 고르는가

축이 둘입니다. 하나는 관리자님의 관심사, 다른 하나는 GeekNews 에서 받은 추천수입니다.

  • 추천 축 — 최근 30일 추천수 분포에서 상위 10%(p90)를 통과한 것은 관심사와 무관해도 싣습니다. 2건에서 5건 사이로 자릅니다. 관심사 밖이라고 다 걸러 내면 시야가 관심사 안쪽으로만 좁아집니다.
  • 관심사 축 — 나머지 자리는 아래 프로필과의 매칭으로 채웁니다. 프로필은 til 아카이브에 쌓인 글에서 자동으로 뽑으므로, 관리자님이 쓰시는 주제가 바뀌면 따라 움직입니다.
  • 정렬 — 추천 백분위가 1순위입니다. 관심사는 순위가 비슷할 때만 끼어듭니다. 주제가 맞는다고 위로 올려 봐야 실제로 안 읽히더라는 것이 파일럿의 결론이었습니다.

중복된 사건, 홍보성 글, 이미 til 에서 다룬 주제의 재탕은 뺍니다. 뺀 것들도 감추지 않고 브리핑 맨 아래 '훑고 넘긴 것' 에 한 줄씩 남겨 둡니다.

지금의 관심사 프로필

  • AI 40% — 음성 서빙, 벤치마크, 추론 벤치마크, 텍스트 워터마킹
  • 워크플로 17% — 백로그 에이전트, AI 코딩과 Go, 개인 프로젝트 결산, 에이전트 스킬
  • 하드웨어 12% — e-ink 웹 UI, e-ink 대시보드, 가젯 카탈로그, 생활가전
  • 시스템 12% — 헤드리스 브라우저, 추천 알고리듬, Lynx와 브라운필드, API 키 설계
  • 터미널 8% — herdr, 쿼터 페이스 색, 비교, 폰트
  • 읽을거리 5% — 수면과 지능 연구 검증, 광치료, 권력과 공감 연구 검증, 하반기 게임 신작 예보
  • 경제 4% — AI 투자 에이전트, AI와 노동, 투자 리서치
  • 사이트 3% — 접수창구 개선, 캐릭터, 아카이브

til 88건에서 자동 추출 · 2026-08-25 기준 · 최근 글에 가중치(반감기 90일)

이 구간은 발행 잡이 til 카드에서 다시 계산해 덮어씁니다. 손으로 고치지 마세요.

수집 범위와 정리 모델

  • GeekNews 새 소식 목록을 첫 쪽에서 끊지 않고 빈 쪽이 나올 때까지 훑습니다(대개 30-40건). 파일럿에서 추천 상위 6% 짜리가 2쪽에 있었습니다.
  • 목록만으로는 밀도가 안 나와서, 고른 것만 개별 페이지를 다시 가져와 본문과 댓글까지 읽습니다.
  • 선별과 정리는 Claude Opus 5 가 합니다. 요약은 원문 저자가 직접 말하는 어투로 옮깁니다.
  • 이미 다룬 항목은 기록해 두고 다음 날 후보에서 뺍니다. 새로 올라온 것이 몇 건 안 되는 날은 모델을 부르지 않고 조용히 넘어갑니다.

버튼은 무엇을 하는가

각 항목의 '이 건으로 TIL 만들기' 는 두 번 누르는 버튼입니다. 한 번 누르면 방향을 적을 칸이 열리고, 한 번 더 누르면 그대로 접수됩니다. 비워 두시면 제가 알아서 방향을 정합니다.

두 번째 클릭에서 접수가 끝납니다. 관리자 제출 페이지 에 등록해 두신 접수함 토큰을 같은 브라우저에서 그대로 쓰기 때문에, 누르면 그 자리에서 접수 번호가 나옵니다. 토큰은 관리자님 브라우저에만 있고 페이지 파일에는 없습니다.

토큰이 없는 브라우저에서는 이슈 작성 화면을 미리 채워 새 탭으로 여는 쪽으로 넘어갑니다. 한 번 등록해 두시면 다음부터는 바로 접수됩니다.

접수되면 원문을 직접 읽고 til 페이지까지 만들어 아카이브에 올립니다. 완성되면 Slack 으로 알려 드립니다.
