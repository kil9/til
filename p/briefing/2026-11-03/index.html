01이메일 암호화 이해하기 - 전송, 저장, 종단 간 암호화의 차이와 한계

이메일 암호화는 어디에 적용하느냐에 따라 막을 수 있는 위협이 다릅니다. 기기와 서버 사이의 연결, 서버 간 전송, 저장 데이터, 종단 간 암호화를 하나씩 나눠 살펴보겠습니다. 그 전에 무엇을 막으려는지부터 정하시길 권합니다. 대부분의 사용자에게 현실적인 위협은 도청보다 계정 탈취와 스팸 오분류 쪽입니다.

  • 서버 간에 쓰는 기회적 TLS 는 상대 서버가 지원하지 않으면 평문으로 내려갑니다. 그래서 STARTTLS 를 지우는 중간자에게 강등될 수 있고, 이를 보완하는 수단이 MTA-STS 와 DANE 입니다. 저희는 DNSSEC 장애 위험을 따져 보고 지금은 DANE 보다 MTA-STS 를 택했습니다.
  • 저장 데이터 암호화는 디스크 도난을 막아 줍니다. 하지만 서비스가 키를 쥐고 있으면 서버 장악이나 적법한 제출 요구까지는 막지 못합니다. 제로 액세스 암호화도 새 메일을 받는 시점과 변조된 웹 클라이언트 앞에서는 한계가 있습니다.
  • 종단 간 암호화는 본문을 강하게 지키는 대신 키 관리, 서버 측 검색, 악성코드 검사를 포기해야 합니다. 일상 메일과 민감한 소통은 나눠서 고르시는 편이 낫습니다.

02AI 시대의 새로운 창업자 유형

AI 가 제품을 만드는 문턱을 낮추면서 1인 창업자, 비개발자, 분야 전문가, 학생, 콘텐츠 크리에이터가 새로운 창업자층으로 올라올 것이라고 봅니다. 다만 첫 제품을 만드는 능력이 회사를 굴리는 능력까지 대신해 주지는 않습니다.

  • 예전에는 두세 명이 나눠 맡던 제품, 기술, 시장 진출을 이제 1인 창업자가 해낼 수도 있습니다. 하지만 모두의 생산성이 함께 오르면 시드 단계에 기대하는 수준도 같이 올라갑니다.
  • 분야 전문가는 현장의 문제를 잘 찾지만, 산업을 새로 짜려면 외부자의 시선이 필요할 때가 있습니다. Airbnb 를 만든 건 호텔업 종사자가 아니었습니다. 크리에이터의 팔로워도 첫 유입은 만들어 주지만 지속적인 성장까지 보장하지는 않습니다.
  • Stanford 박사, 중퇴자, 디자인 감각 있는 창업자처럼 투자자가 선호해 온 전형은 그 시대의 기술과 유통 채널이 만든 것입니다. 이제는 기존 평가 기준 가운데 본질적인 조건과 한 시대의 산물을 가려내야 합니다.

03학자의 의무

지식을 가진 사람의 의무는 진실을 숨기지 않는 데서 끝나지 않는다고 생각합니다. 그 지식이 필요한 사람을 직접 찾아가 전하는 데까지 이어집니다. Intel Hyper-Threading 취약점을 공개하기까지 6개월을 쓴 경험에서 이 이야기를 시작합니다.

  • 2004년 말 Hyper-Threading 의 캐시 공유를 이용해 RSA 개인키를 복원하는 개념 증명을 만들었습니다. 그 뒤 논문 수정과 구직을 미루고 약 6개월을 보안팀과의 공개 조율에 썼습니다. 미혼이었고 부모님 집 지하에서 지낼 수 있었으며 캐나다의 의료 체계가 있었기에 가능했던 일입니다.
  • 의무는 안전이나 보안 문제에만 걸려 있지 않습니다. 2009년에 EC2 방화벽이 Path MTU Discovery 를 방해한다는 사실을 Amazon 에 알렸습니다. 2012년 11월까지 고쳐지지 않자 고객이 직접 고치는 방법을 공개했고, 그제야 수정이 나왔습니다.
  • 지식을 전할 의무와 행동을 강요할 권한은 다른 것입니다. 행동할 수 있는 사람이 모두 알게 됐다면 의무는 끝난 것이고, 상대에게는 그 지식을 거절할 자유가 있습니다. 학자는 철인왕이 아닙니다.

04OpenQodex - 코딩 에이전트의 변경을 별도 에이전트가 검증하는 코드 리뷰 도구

코딩 에이전트가 만든 변경을, 이미 로그인해 둔 계정으로 별도의 Claude Code 나 Codex 프로세스가 리뷰하게 하는 도구입니다. 문제를 찾는 세션과 검증하는 세션을 나눴습니다. 그래서 한 세션이 찾은 문제를 다른 세션이 코드와 정적 분석 결과를 보고 확인하거나 반박합니다.

  • 기본으로 아직 푸시하지 않은 커밋과 커밋하지 않은 변경 전체를 검사합니다. 비밀키, 의존성, 린트, CI 와 인프라 설정, SQL 등을 보는 내장 스캐너 22개도 함께 돌립니다.
  • 리뷰가 인용한 코드가 실제로 존재하는지, 변경 구간이 리뷰어에게 빠짐없이 전달됐는지도 검사합니다. 검토가 끝나지 않으면 누락된 부분을 표시합니다.
  • 결과는 HTML, Markdown, JSON, SARIF 로 받을 수 있고, 푸시 전 경고와 심각도별 차단도 지원합니다. 리뷰어로는 Claude Code 와 Codex 만 쓸 수 있습니다. 댓글에서는 verifier 가 테스트까지 직접 돌리는지 README 에 나와 있지 않다는 지적이 나왔습니다.

05AI 토큰 경제의 현주소: CFO가 알아야 할 것

OpenRouter 의 주간 처리량은 2025년 1월 약 5,000억 토큰에서 2026년 9월 말 164조 토큰으로 늘었습니다. 같은 기간 100만 토큰당 평균 지불 가격은 0.77달러에서 0.14달러로 내려갔습니다. AI 추론은 이제 연간 계약으로 사는 소프트웨어보다 원자재처럼 다뤄야 합니다.

  • 오픈 웨이트 모델이 주간 토큰의 약 60% 를 처리하지만 지출 비중은 26% 에 그칩니다. 분류, 추출, 코딩 하위 작업 같은 일상 업무가 훨씬 싼 모델로 옮겨 갔기 때문입니다.
  • 2026년 2월 6일 에이전트가 쓰는 토큰이 사람의 사용량을 넘어섰습니다. 에이전트는 긴 문맥을 매 단계 다시 보내므로 프롬프트 캐싱이 가격을 좌우합니다. 이번 분기에 나온 모델은 에이전트 트래픽의 88% 를 캐시합니다.
  • 인기 오픈 웨이트 모델 3개의 실제 지불액은 표시 가격으로 계산한 값보다 43-89% 낮았습니다. 표시 가격이 가장 싼 공급업체가 실제로도 가장 싼 것은 아니었습니다. 대기와 재시도, 장애 시 대체 경로까지 넣은 총비용으로 판단하십시오.

06Anthropic, Claude의 게임 재구현 제한 시작…모딩과 역공학 작업 거절 사례도 보고

Anthropic 은 Claude Code 의 Opus 5.5 프롬프트에 다른 사람의 특정 게임을 재구현하지 않도록 하는 두 문장을 넣었다고 확인했습니다. 지식재산권 침해를 막으려는 조치이며, 독창적인 게임이나 사용자 자신의 디자인과 에셋을 쓰는 개발은 계속 지원한다는 설명입니다.

  • 확인된 규칙은 이름을 바꾸거나 독창적이라고 불러도 특정 기존 게임의 재구현을 막는다는 내용입니다. 역공학이나 모딩 전반을 금지한다고 적혀 있지는 않습니다. 그런데 진행 중인 게임 프로젝트나 일반 개발 작업까지 거절됐다는 제보가 있고, 이것이 같은 규칙 때문인지는 확인되지 않았습니다.
  • 제한이 강화된 배경으로 몇 가지가 거론됩니다. AI 로 게임 코드 분석과 개조, 브라우저 이식이 쉬워졌고, PS5 탈옥으로 다른 플랫폼의 게임까지 돌아가면서 소송 위험이 커졌다는 것입니다.
  • 학습에는 남의 콘텐츠를 폭넓게 쓰면서 이용자의 침해는 막는다는 모순을 지적하는 비판이 따라붙었습니다. 악용하려는 사람은 제한 없는 다른 모델로 옮겨 갈 뿐이라는 지적도 있습니다. HN 댓글도 대체로 이쪽입니다.
