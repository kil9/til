01브라우저 실시간 통신 설계: 폴링·SSE·WebSocket과 상태 복구

실시간이라는 요구를 보면 WebSocket 부터 떠올리기 쉽지만, 채팅·완료 알림·협업 커서는 기다릴 수 있는 시간도, 끊겼을 때 되찾아야 하는 것도 다릅니다. 그래서 전송 수단을 고르기 전에 무엇을 어디까지 약속할지부터 정해야 합니다. 연결이 열렸다는 것과 화면이 최신이라는 것은 서로 다른 사실입니다.

  • 요구사항에는 허용 지연과 달성 비율, 통신 방향과 빈도, 놓친 것을 되찾는 방법을 적어야 합니다. 지연(latency)과 최신성(freshness)은 다른 요구입니다.
  • SSE 의 Last-Event-ID 나 WebSocket 재연결만으로는 누락분이 돌아오지 않습니다. 서버가 이벤트를 보관하고 재생해야 하고, open 이벤트는 동기화가 끝났다는 뜻이 아닙니다.
  • 목록을 조회한 뒤 구독하면 그 사이의 변경이 빠집니다. 스냅샷과 그 스냅샷에 대응하는 커서를 함께 받아, 그 커서부터 구독해야 합니다.

03NSL - Linux용 WSL

nsl(NSpawn Subsystem for Linux)은 개발 도구와 의존성을 호스트 대신 별도의 Linux 머신에 설치해, 기존 시스템을 건드리지 않고 개발하게 해 줍니다. 각 머신은 공유 VM 안의 systemd-nspawn 컨테이너로 돌고, 패키지·서비스·파일이 세션 사이에도 남습니다. WSL2 의 사용감을 Linux 에서 그대로 얻고 싶어서 만들었습니다.

  • 호스트와 같은 사용자 이름·UID·GID 를 써서 파일 소유권이 유지되고, 포워딩된 포트는 127.0.0.1 로, Wayland 앱은 Waypipe 로 호스트에서 씁니다.
  • 신뢰하지 않는 소프트웨어는 --isolated 로 전용 VM 에서 돌려 호스트 파일과 데스크톱 접근을 막습니다. Debian·Fedora·Arch 등 서명된 이미지 7종을 매주 다시 빌드합니다.
  • v0.4.0 이 현재 설계의 첫 릴리스이고 안정 버전은 아직 없습니다. HN 에서는 toolbx 와 무엇이 다르냐는 질문이 나왔습니다.

08판단 전용 모델 Laya 실측 – 정확도 78%, 틀린 답에도 confidence 0.9 (파인 튜닝전에 데이터)

개인 Obsidian 플러그인의 중복 노트 판단(지금은 OpenAI API)을 오픈소스 판단 모델 Laya 로 바꿀 수 있는지 직접 재 봤습니다. 23건 중 18건, 78% 를 맞혔습니다. 그런데 진짜 문제는 정확도가 아니라 캘리브레이션이었습니다.

  • 맞힌 답에도 confidence 가 0.01 수준인 경우가 많았고, 완전히 다른 노트를 같다고 틀리면서 0.802, 0.896 을 붙인 경우가 있었습니다. 로드 시점에 temperature 값이 손상됐다는 경고가 이미 떠 있었습니다.
  • README 의 33ms 는 Tesla T4 GPU 수치였고, GPU 없는 12코어 PC 에서는 콜드 로딩 23초, 호출당 1.3초가 걸렸습니다. Hugging Face 의 GGUF 파일도 llama.cpp 표준이 아니었습니다.
