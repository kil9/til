01AI가 쓴 글은 왜 이해하기 어려울까?

AI가 쓴 대화, 코딩 설명, 에세이를 사람 글과 비교해 보니 읽는 사람에게 부담을 주는 표현이 더 자주 나왔습니다. 조사한 상위 모델 9개 모두 무생물 주어에 사람 행동 동사를 붙였고, 흔하지 않은 단어 조합을 썼습니다. 저희는 수학과 코딩의 정답을 맞히는 학습이 적은 토큰에 정보를 눌러 담게 만들고, 이것이 사람에게 전달하는 능력과 어긋난다고 봅니다.

  • 같은 문장을 영어에서 일본어로 옮겼다가 다시 영어로 되돌리면 이런 특징이 줄어듭니다. 내용이 아니라 표현을 고르는 방식에서 차이가 난다는 뜻입니다.
  • 대화에서는 긴 구문 의존 관계, 명사 연쇄, 축약된 목적격 관계절도 늘었고, 모델 계열마다 쓰는 양상이 꽤 달랐습니다.
  • 작은 모델에 긴 답변을 벌점으로 주는 강화학습을 걸자 학습하지 않은 문장 구조에서도 짧은 표현을 골랐습니다. 압축 압력이 문법 선택까지 바꿀 수 있다는 개념 증명입니다.

02우리가 만드는 소프트웨어에 더 큰 야심을 가져야 한다

AI로 소프트웨어를 만드는 비용이 내려가면서, 예전에는 혼자 감당하지 못했을 큰 프로젝트도, 시간 대비 가치가 없어 접었던 개인 도구도 만들 수 있게 됐습니다. 저는 정규식 엔진, ripgrep 포크, Rust 개발 도구를 직접 몇 시간 들여 제 환경에서 돌아가는 수준까지 만들었고, 예전이라면 1년 넘게 걸렸을 일로 봅니다. 더 야심 차야 한다는 의무가 아니라 그럴 수 있게 됐다는 이야기입니다.

  • 남들이 저품질 결과물을 쏟아낸다고 같은 수준에 머물 필요는 없습니다. pgrust는 검증하는 과정에서 SP-GiST, JSONPath, pgcrypto, money 오버플로 같은 Postgres 버그를 실제로 찾아냈고, 프로젝트가 실패하더라도 그 수정은 남습니다.
  • 다만 모델의 구현 능력이 늘어도 검증 능력이 함께 따라오지는 않습니다. 결과를 판별할 전문성과 테스트 구조를 갖춰야 도전 범위를 넓힐 수 있습니다.
  • pgrust의 Clickhouse 벤치마크 논란은 미리보기 버전을 너무 일찍 제출한 문제로 보입니다. 한계를 공개적으로 인정하는 Malis의 태도는 데이터베이스 업계에 흔한 성능 과장과 대비됩니다.

04JetBrains Thinkrail - 명세로 프로젝트 지식을 유지하는 에이전트 IDE

ThinkRail은 pi 코딩 에이전트에 편집기, 터미널, 검토 도구를 붙인 IDE입니다. 코드 옆에 SPEC.md 그래프를 두고 에이전트가 전용 도구로 읽고 고치게 해서, 세션이 끝나도 프로젝트의 의도가 남도록 했습니다. 작업공간은 git worktree로 나눠 에이전트 여럿을 병렬로 돌립니다.

  • 변경 검토, GitHub PR 생성, CI 확인, 병합까지 한 흐름으로 이어지고, PR이 닫혔거나 일주일 동안 활동이 없는 작업공간은 보관 선반으로 옮깁니다.
  • 다른 코딩 에이전트용으로 둔 Agent Skills를 원래 위치에서 그대로 읽고, 작업공간마다 pi 세션 여러 개를 돌리면서 세션별 모델, 토큰, 비용을 따로 보여 줍니다.
  • 기본 사용 이벤트와 오류 보고는 무작위 설치 ID에 묶어 수집하며, 프롬프트나 코드, 파일 경로는 담지 않는다고 밝혔습니다.

05그래프와 LLM 북키핑 없이 AI 메모리 구현하기 - 입력 토큰 95% 절감

저희는 대화 원문을 그대로 보관하다가 질문이 오면 필요한 구절만 찾아 답변 모델에 넘깁니다. 지식 그래프도 만들지 않고, 생성형 LLM으로 기억을 추출하거나 요약하지도 않습니다. 그래도 LongMemEval-S 500문항에서 정확도 96.0%가 나와, 전체 대화를 넣은 방식의 95.2%와 비슷했습니다.

  • 평균 답변 입력은 105,183토큰에서 4,886토큰으로 95.35% 줄었습니다. 500건 실행 비용은 7.51-9.42달러로, 전체 대화 방식의 105.53달러보다 91-93% 낮게 추정했고, 이 가운데 재정렬과 저장 비용은 모델링한 값입니다.
  • 대화를 출처와 시각이 붙은 청크로 저장하고, 임베딩 생성, 하이브리드 검색, Jev 재정렬을 검색 요청 한 번에 처리합니다.
  • BEAM 평가에서도 past.dev 공개 결과와의 차이가 3.1-4.4점이었고, 대화 이력이 커져도 평균 입력은 약 1만 3,000토큰을 유지했습니다. 구현은 SillyTavern 확장인 SillyMemory로 공개했습니다.
