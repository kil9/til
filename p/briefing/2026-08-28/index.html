02Engineerification - 전문직이 엔지니어처럼 변해간다

수학자, 디자이너, 분석가, 법률가의 작업 방식에 저장소, 에이전트, 테스트, 형식 명세, 피드백 루프가 들어오고 있다. 이걸 engineerification이라 부르자. 핵심은 모두가 코딩을 배운다는 뜻이 아니라, 도메인 전문가가 일을 직접 하는 자리에서 일을 대신하는 시스템을 만들고 감독하고 고치는 자리로 옮겨간다는 것이다.

  • 브라질 IMPA 강연은 수학자에게 로컬 디렉터리 작업, 에이전트 권한 제한, 저장소 커밋, 지침 파일 작성, Lean 형식 검증을 권했고, 어떤 수학자는 하루를 프로젝트 디렉터리로 이동해 에이전트를 띄우는 것으로 시작한다.
  • 소프트웨어에서 이 변화가 먼저 왔다 — 2024년 무렵 위임 단위가 자동완성에서 저장소로 커지면서 테스트와 명세, 아키텍처가 사람과 구현 사이의 인터페이스가 됐다.
  • 다만 시스템으로 바꾸는 과정에서 표현 가능한 입력과 규칙만 중요해질 위험이 있고, 감독마저 AI가 맡는다면 engineerification은 최종형이 아니라 일시적인 인터페이스일 수 있다.

03요일 계산을 더 빠르게 만드는 방법

32비트 날짜 카운트에서 요일을 구하는 % 7은 실제 기계어에서 여러 곱셈과 보정 연산으로 풀린다. 7 = 2^3 - 1인 메르센 수 성질을 쓰면 % 7을 % 8에 가까운 연산으로 바꿀 수 있고, 제한 범위에서는 곱셈·덧셈·시프트 세 연산이면 끝난다.

  • 핵심 항등식은 N % 7 = floor(N * 8 / 7) % 8이며, /7을 고정소수점 역수 곱셈으로 근사하고 상위 3비트만 남기면 % 8은 공짜로 처리된다.
  • 전체 32비트 범위는 round-down multiplier에 (rd >> 1) + (rd >> 4) 보정을 더해 처리하는데, 보정항이 곱셈 결과가 아니라 원래 입력에만 의존해 슈퍼스칼라 CPU에서 병렬로 돈다.
  • Ryzen 9과 M4 Pro 벤치마크에서 기존 기준인 Neri 2024 방식의 0.3-0.5배 시간에 실행됐고, 같은 원리를 % 3, % 15, % 31과 x % 24, x % 60에도 확장할 수 있다.

04Tailcat - Tailscale 계정 없이 두 머신을 연결하는 netcat

Tailscale의 magicsock, WireGuard, DERP, 사용자 공간 네트워크 스택만 떼어내 계정도 제어 서버도 없이 두 머신을 잇는 netcat이다. 서버가 뱉은 50바이트짜리 토큰을 아무 경로로든 상대에게 넘기면 표준 입출력이나 TCP 포트가 암호화 터널로 연결된다. 스스로를 'Tailscale이 만든, Tailscale 없는 Tailscale' 이라 부르는 이유다.

  • 연결은 DERP 릴레이로 시작해 STUN과 UDP 홀 펀칭에 성공하면 직접 P2P 경로로 전환하고, 실패하면 릴레이를 계속 쓴다 — 터널 내부는 DERP에서도 해독되지 않는다.
  • gVisor Netstack이 프로세스 안에서 TCP를 처리해 커널 TUN 장치도, 라우팅·DNS 변경도, root 권한도 필요 없다.
  • --serve로 포트 전달·SSH·SOCKS5·exit node를 열 수 있고, 기본 키는 프로세스가 끝나면 폐기되지만 genkey로 고정 주소를 만들고 --allow로 클라이언트 공개 키를 제한할 수도 있다.

05Corsair - AI 에이전트의 외부 서비스 연결과 권한을 관리하는 통합 레이어

AI 에이전트가 Gmail, Slack, GitHub, Notion, Stripe를 호출할 때 필요한 도구와 자격 증명, 실행 권한을 한 레이어로 묶는 TypeScript 라이브러리다. MCP로 붙이거나 SDK로 직접 넣어 쓰고, 필요한 통합만 패키지로 설치해 등록한다. 에이전트에는 메서드와 결과만 넘어가고 API 키와 OAuth 토큰은 호출 시점에 내부에서만 꺼낸다.

06Git을 어떤 규모에서도 확장하는 법 - Cursor의 새 Git 저장 시스템 Continuity

Git은 로컬에선 단순하지만 서버에서 대규모로 호스팅하면 packfile의 랜덤 접근, 강한 일관성 요구, 복제 비용 때문에 급격히 어려워진다. Continuity는 Git 저장소 대신 S3의 Write-Ahead Log를 진실의 원천으로 두고, 로컬 저장소는 언제든 다시 만들 수 있는 캐시로 취급한다.

  • GitHub의 Spokes는 로컬 NVMe에 실제 저장소를 두고 3-phase commit으로 reference를 동기화해 업계 표준이 됐지만, 대형 monorepo에는 3 replica의 천장이 너무 낮고 에이전트가 만드는 수많은 작은 저장소에는 바닥이 너무 높다.
  • Git 객체를 분산 KV 스토어에 넣는 접근은 commit → tree → blob을 순차로 따라가야 해 단계마다 네트워크 왕복이 생기고, JGit + DHT 시도도 결국 packfile 전송 때문에 폐기됐다.
  • Continuity는 모든 push가 WAL에 완전히 기록된 뒤에야 성공 처리되고 S3의 CAS로 직렬화되며, replica는 읽기 직전 WAL 상태만 확인해 합의 프로토콜 없이 일관된 뷰를 준다.
