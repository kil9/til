02sutura - AI 에이전트가 회사의 지표 정의로 데이터를 조회하게 해주는 쿼리 엔진

대시보드에서 보던 매출을 에이전트에게 물어도 회사가 정해 둔 같은 기준으로 계산되게 하려고 sutura 를 만들었습니다. 지표·분류 기준·기간·집계 단위만 받고 임의 SQL 이나 필터 표현식은 받지 않으며, Rust 엔진이 지표 정의에서 SQL 을 만들어 기존 데이터베이스나 웨어하우스에서 실행합니다.

  • 카탈로그로 DataHub·OpenMetadata·Markdown 을 연결할 수 있고 Cube 정의도 쓸 수 있어 BI 와 에이전트가 같은 정의를 봅니다. PostgreSQL·BigQuery·ClickHouse·Oracle·DuckDB 를 지원하고, 여러 소스에 걸친 질의는 소스별로 실행한 뒤 DataFusion 에서 합칩니다.

03자율 에이전트를 위한 데이터 플랫폼 구축

에이전트가 데이터 플랫폼을 운영하려면 시맨틱 모델만으로는 부족합니다. 매출 감소를 정확히 계산하고도, 실제 원인이 지난주 수집 장애나 최근 배포로 바뀐 집계 구간이라는 걸 모르면 틀린 답을 권위 있게 내놓습니다. 그래서 데이터의 최신성·완전성과 파이프라인 실행 상태까지 볼 수 있어야 합니다.

  • 연결된 관측: Airflow 태스크, EMR 스텝, Spark 애플리케이션 로그를 같은 실행으로 이어 두자 에이전트가 최초 장애와 후속 증상을 구분할 수 있었고, Foursquare 의 주요 파이프라인에서 Spark 문제 진단·해결 시간이 최대 90% 줄었습니다.
  • 비즈니스 맥락: 데이터 계보만으로는 목적을 알 수 없으니 파이프라인마다 목적·적용 범위·완료 기준·소유자를 선언하고, 그 선언을 DAG 코드와 함께 버전 관리합니다.
  • 통제된 실행: 에이전트의 권한은 지침이 아니라 실행 시스템이 강제하는 경계여야 하고, 데이터 접근·코드 수정·실행 환경 권한을 나눠야 합니다.

05LLM은 신경망 가중치를 읽고 쓰는 데 초인적이지 않다

GPT-6 Astra 가 작은 신경망의 가중치만 보고 어떤 게임을 학습했는지 맞히고 0.8B Qwen 의 수학 성능을 올린 건 인상적입니다. 그래도 유능한 인간 ML 연구자가 할 수 있는 일이라, 초인적이라고 부르기는 어렵다고 봅니다.

  • 게임 신경망은 입력 채널이 8×8 격자 칸에 직접 연결되고 이름까지 붙어 있어서, 첫 층 가중치의 L2 노름 히트맵만 그려도 Breakout 의 아래쪽 수평선이나 Pac-Man 의 미로가 드러납니다.
  • Qwen 개선은 수학 능력을 새로 심은 게 아니라 32k 토큰 이후 반복에 빠지는 문제를 고친 결과입니다. 반복하는 추론과 아닌 추론을 비교해 관련 가중치를 줄인 방식은 Heretic 의 abliteration 과 같은 계열입니다.
  • 바이너리를 고치는 가장 좋은 길이 여전히 소스를 고쳐 다시 컴파일하는 것이듯, LLM 의 연구 기여도 가중치를 직접 고치기보다 학습 개선에서 나올 겁니다. HN 에서는 히트맵만으로 게임을 맞히기는 어렵다는 반론이 나왔습니다.

08Alpine Linux 보안 권고: OpenSSH 서버 비밀번호 인증 우회

Alpine Linux Security Advisory: OpenSSH-server password authentication bypass

Alpine Linux 의 OpenSSH 서버에서 비밀번호 인증을 우회할 수 있는 문제가 있어 보안 권고를 냅니다. OpenSSH 쪽에서도 PAM 없이 도는 Alpine 을 위한 10.6p2 긴급 우회 조치가 나왔습니다.

  • HN 댓글이 정리한 원인은 이렇습니다. musl 의 crypt() 는 키가 256바이트를 넘으면 오류 표시로 문자열 '*' 를 돌려주는데, 비밀번호 없는 계정의 저장 필드도 정확히 '*' 라서 '해시'가 일치하고 로그인이 통과됩니다.
  • 같은 댓글은 POSIX 가 실패 시 널 포인터와 errno 를 요구한다는 점을 들어 musl 의 선택을 의아해했고, 다른 댓글은 이제 C 를 벗어나야 한다는 주장으로 번졌습니다.
