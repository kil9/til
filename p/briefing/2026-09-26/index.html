01Archify - 코드와 설명을 탐색 가능한 시스템 다이어그램으로 만드는 에이전트 스킬

코드베이스를 분석시키거나 시스템을 말로 설명하기만 하면, 구성 요소와 연결 관계를 직접 따라가 볼 수 있는 다이어그램을 만들어 드립니다. 에이전트는 구조화된 JSON만 쓰고 HTML/SVG 변환은 Node.js 렌더러가 맡기 때문에, JSON을 고쳐 가며 대화로 결과를 다듬을 수 있습니다.

  • 아키텍처·워크플로·시퀀스·데이터 흐름·생명주기 다섯 유형을 지원하고, Cursor·Claude Code·Codex CLI·OpenCode에서 npx skills add tt-a1i/archify -g 한 줄로 설치합니다.
  • 생성 중에 데이터 구조, 배치, 연결선과 글자 간격을 검사해서 틀린 곳이 있으면 고칠 위치와 원인을 돌려주고, 요청하면 노드에 특정 Git 커밋의 소스 파일과 코드 위치를 연결해 근거로 삼습니다.
  • 변경 전후 다이어그램을 비교해 추가·삭제·이동된 요소를 표시하고, 결과는 단일 HTML과 PNG/SVG/WebM으로 내보냅니다. 이미 설치해 쓰는 사람의 댓글은 개발 중에 시각화를 부탁하면 이 스킬로 보여 줘서 쓸 만하다는 평이었습니다.

05최신 ESP32, Linux를 실행하며 Raspberry Pi에 가까워지고 있음

ESP32-S31에는 Sv32 페이지 테이블과 Machine·Supervisor·User 권한 모드를 갖춘 제대로 된 MMU가 들어가, 일반 RISC-V Linux를 돌릴 하드웨어 기반이 생겼습니다. 기가비트 Ethernet, USB 호스트, 카메라·디스플레이 인터페이스까지 달려서 쓰는 모습은 이제 SBC에 가깝습니다.

  • 320MHz RISC-V 코어 두 개에 PSRAM은 최대 64MB, GPU는 없습니다. 그래서 Linux 데스크톱이 아니라 터미널을 띄우는 수준이고, 커널은 PSRAM을 아끼려고 플래시에서 실행합니다.
  • Espressif가 8월에 Buildroot·U-Boot 기반 Linux BSP를 공개했지만 프로덕션용은 아니고, 커뮤니티에서는 Linux 6.18 포트와 800×480 LCD에 콘솔을 띄우는 7.1 포트가 나와 있습니다.
  • Wi-Fi 6, Classic까지 되는 Bluetooth 5.4, Thread/Zigbee를 갖추고도 소비 전력은 마이크로컨트롤러 수준입니다. HN에서는 ESP32라는 이름 아래 성능 폭이 너무 넓어졌다는 불만과, P4로 지터 없는 기타 페달을 만든다는 경험담이 나왔습니다.
