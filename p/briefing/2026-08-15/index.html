04Wails v3 Beta - Go 데스크톱 앱을 위한 새로운 기반

Wails v3를 베타로 올립니다. 2023년 1월 첫 알파 이후 3년이 넘었고, 그동안 한 일은 단순한 버전 업이 아니라 애플리케이션 구조 자체의 재설계입니다. 가벼운 Electron 대체제를 넘어 복잡한 데스크톱 앱을 만들 수 있는 기반으로 옮겼습니다.

  • wails.Run과 암묵적 컨텍스트 구조를 버리고 Application·Window·Service를 명시적인 객체와 수명주기로 다루도록 바꿨습니다. 멀티윈도우가 기본 기능이 되어 에디터·Inspector·Preferences 같은 창 구성을 우회 없이 만들 수 있습니다.
  • binding 대신 Go Service를 도입해 백엔드 기능과 프론트엔드 노출 API의 경계를 나눴고, Go 소스를 정적 분석해 TypeScript 바인딩을 생성하므로 주석과 파라미터 이름까지 보존됩니다.
  • 빌드 과정을 프레임워크 안에 숨기지 않고 Taskfile로 공개했으며, 네이티브 창 없이 같은 구조를 돌리는 Server Build도 지원합니다. 다만 v2는 여전히 안정 버전이고 v2에서 v3는 실질적인 포팅 작업입니다.

07MCP가 Stateless해짐

MCP 2026-07-28은 출시 이후 가장 큰 스펙 변경입니다. 프로토콜 코어를 stateful 양방향 연결에서 stateless request/response로 바꿨고, initialize handshake와 Mcp-Session-Id를 제거했습니다. 이제 remote MCP 서버를 평범한 HTTP 서비스처럼 로드밸런서 뒤에 여러 인스턴스로 두고 굴릴 수 있습니다.

  • 요청 처리에 필요한 protocol version·client identity·capabilities가 요청 자체에 담기므로 어느 인스턴스가 받아도 독립적으로 처리됩니다. capabilities를 미리 알아야 하면 새 server/discover RPC를 선택적으로 씁니다.
  • 서버가 사용자 입력을 요청하는 흐름은 Multi Round-Trip Requests로 재설계됐습니다. 연결을 열어 두는 대신 input_required를 반환하고, 클라이언트가 inputResponses와 requestState를 실어 다시 호출합니다.
  • Mcp-Method·Mcp-Name 헤더로 body 파싱 없이 라우팅·인가·레이트리밋이 가능해졌고, 목록 결과에 ttlMs·cacheScope가 붙었습니다. Roots·Sampling·Logging은 deprecated이며 최소 12개월 유예를 두는 deprecation 정책도 도입됐습니다.

08AI한테 넘기면 싸질 줄 알았다 — 넘길 때마다 붙는 비용 두 개

서브에이전트에 일을 넘길 때마다 고정비 두 개가 붙습니다. 넘겨받은 쪽은 메인 세션의 프롬프트 캐시를 공유하지 못해 코드와 프로젝트 관례를 매번 처음부터 다시 읽고, 지시서를 쓰는 것 자체가 토큰입니다. 이 두 비용은 일의 크기와 무관하게 붙습니다.

  • 그래서 파일 몇 개짜리 작업, 한 번 쓰고 버릴 스크립트, 원인을 이미 아는 버그는 직접 하는 쪽이 쌉니다. 위임이 이기는 건 산출물이 고정비를 압도할 때, 즉 대량 일괄 변경이나 병렬로 쪼갤 수 있는 작업입니다.
  • 위임과 직접 실행은 고를 수 있는 것 자체가 다릅니다. 위임에서 고르는 건 누구에게 맡길지 하나뿐이고 모델과 사고 깊이는 그 대상의 고정 속성입니다. 판정 순서는 명세 확정, 물량, 병렬성이며 목표가 흐릿한데 물량부터 보고 넘기는 것이 가장 비싼 실수입니다.
  • 결론은 절약률이 아닙니다. 같은 일을 직접과 위임으로 나란히 재본 적이 없으면 비용 비교는 안 재봤다고 말해야 하며, 측정 방법 없는 절감 퍼센트는 장식입니다.
