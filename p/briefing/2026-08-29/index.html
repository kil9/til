031.1.1.1 DNS 캐시 최적화로 메모리 100TB 절감

Big Pineapple은 항상 2,500억 개가 넘는 DNS 캐시 항목을 들고 있습니다. 이 규모에서는 항목당 1바이트만 낭비해도 플릿 전체에서 250GB가 사라집니다. 저장 구조를 다섯 차례 고쳐 항목당 953바이트를 420바이트로, 56% 줄였고 전체로는 약 100TB를 확보했습니다.

  • 캐시에 들어간 DNS 응답은 다시 수정되지 않으므로 Vec의 용량 필드와 여분 힙 공간이 필요 없습니다. Box<[T]>·Box<str>로 바꿔 항목당 8개 필드에서 64바이트를 줄였고, 과잉 할당된 힙까지 합쳐 15TB 이상을 확보했습니다.
  • answer·authority·additional 세 목록을 하나로 합치고 섹션 시작 오프셋만 u16 2바이트씩 두어 항목당 28바이트를 줄였습니다. 불리언들을 비트 플래그로 묶자 주변 패딩까지 줄어 필드에서 뺀 바이트보다 구조체가 더 많이 작아졌습니다.
  • 레코드 소유자가 질의 도메인과 같으면 이름을 아예 저장하지 않고 조회 시 캐시 키에서 복원합니다. 조회 경로에서는 캐시 키를 어차피 들고 있으므로 대부분의 레코드가 별도 소유자 할당을 잃었습니다.
  • 벤치마크에서 항목당 할당은 1.1KB에서 461바이트로 58% 감소, 삽입 처리량은 62만5천에서 89만3천으로 43% 증가, 조회 지연은 828ns에서 670ns로 19% 감소했고, 프로덕션 p99 인스턴스 메모리는 9.3GB에서 5.3GB로 떨어졌습니다.

04Agent Behavior - AI 에이전트의 반복 행동을 문서화해 평가 기준으로 삼는 표준

장시간 돌며 수백 번 판단하는 에이전트를 최종 결과 하나로 평가하기는 어렵습니다. 그래서 작업 과정에서 반복적으로 나타나야 할 행동을 문서로 적어 두는 개방형 포맷을 제안합니다. 무엇을 확인하고, 무엇을 판단하며, 어떻게 실행하고, 정보가 부족하거나 실패했을 때 어떻게 복구하는지를 씁니다.

  • 일회성 작업 절차나 도구 사용법이 아니라 비용·안전·정확성처럼 여러 작업에 걸쳐 계속 지켜야 하는 것을 다룹니다.
  • 행동 스펙은 .agents/behaviors/<name>/BEHAVIOR.md 에 두고 YAML frontmatter의 name·description과 자유 형식 Markdown 본문으로 구성하며, 의도·확인할 증거·판단·실행·복구·실패 유형으로 나누기를 권장합니다.
  • 이건 에이전트를 돌리는 시스템 프롬프트가 아닙니다. 시스템 프롬프트와 스킬이 행동을 구현하고, eval이 그 행동이 실제로 나타났는지 재고, 트레이스가 한 일을 기록하는 구조에서 '무엇이 좋은 행동인가'를 먼저 정의하는 자리입니다.
