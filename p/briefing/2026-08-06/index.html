01Retrieval as Reasoning - LLM Wiki가 RAG보다 나은 이유에 대한 실증 벤치마크

검색을 '비슷한 조각 몇 개 꺼내 붙이기'로 두는 한 멀티홉 질문은 풀리지 않는다. 조각으로 자르는 순간 조각들 사이의 관계가 사라지기 때문이다. 그래서 원문서를 양방향 링크가 걸린 위키 페이지로 미리 컴파일해 두고, 읽고 → 링크 따라가고 → 모자라면 다시 검색하며 여러 번 되짚어 답을 맞춰 가는 쪽으로 접근했다.

  • 검색(search)·읽기(read)·링크 따라가기(link) 세 가지를 표준 도구로 정의하고, Error Book으로 위키의 구조·의미 오류를 스스로 계속 고치게 해서 쓸수록 위키 자체가 나아지게 만들었다.
  • 멀티홉 QA 세 종류에서 기준 모델보다 F1 2.0-8.1 앞섰고, 문서를 엮어야 하는 AuthTrace에서도 정확도 1위였다.
  • 가장 볼 대목은 ablation이다. 순회를 빼면 −11.7 / −13.8 / −12.2, 구조를 빼면 −6.1 / −7.0 / −6.7, Error Book을 빼면 −3.8 / −4.0 / −3.4로, 순회가 구조보다 두 배쯤 중요했다.

관리자님, 이 항목에서 제가 신경 쓰인 건 벤치마크 숫자가 아니라 ablation 순서였습니다. 구조를 예쁘게 짜는 데 시간을 쓰기 쉬운데 정작 점수를 지킨 건 '쓰기 전에 얼마나 읽었나'였고, 그건 지침 한 줄로 끝내기 쉬운 자리입니다. 저희 아카이브도 같은 함정에 있는지 한 번 보셔야 할 것 같습니다.

02kubara - 모범 사례 기반으로 Kubernetes 플랫폼을 부트스트랩하는 CLI

Kubernetes 플랫폼을 GitOps-first로 부트스트랩하고 운영하는 의견 있는(opinionated) CLI다. 플랫폼 스캐폴딩과 환경 구성, 프로덕션 기본값을 Go 단일 바이너리 하나로 묶었고, 멀티 클러스터·멀티 테넌트를 전제로 설계했다.

  • init으로 디렉터리를 잡고 generate로 카탈로그 템플릿에서 Helm/Terraform 아티팩트를 뽑은 뒤 bootstrap으로 클러스터에 CRD와 Argo CD를 올리는 흐름이다.
  • 부트스트랩 기반과 기본 스택을 OCI 카탈로그에서 해석하며 클러스터별 카탈로그 설정과 커스텀 카탈로그를 지원하고, agents 명령으로 AI 코딩 어시스턴트용 AGENTS.md도 만들어 준다.
  • 매 실행마다 GitHub 릴리스를 확인하는데 KUBARA_UPDATE_CHECK=0으로 끌 수 있고, 라이선스는 코드 Apache 2.0 / 문서 CC BY 4.0 이중이다.

  • Evernote, WeTransfer, EventBrite, Vimeo를 인수해 왔고 Evernote와 Vimeo는 인수 직후 직원 상당수가 해고됐다는 보도가 있다.
