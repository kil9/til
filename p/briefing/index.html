02고마워요, Deno - 경쟁이 바꾼 JavaScript 생태계

Deno는 독립 런타임으로는 크게 퍼지지 못했지만, 던진 도전은 JavaScript 생태계 곳곳에 남았습니다. Node를 떠나지 않은 개발자도 웹 표준 API, 권한 모델, 빌드 없는 TypeScript 실행 같은 경쟁의 결과를 누리고 있습니다. 프로젝트가 시장에서 이기지 못해도 아이디어는 다른 도구에 남아 사용자에게 돌아옵니다.

  • Deno 팀은 Cloudflare에 합류하고, Deno 런타임은 앞으로 1년에 걸쳐 투자를 줄입니다. JSR은 Cloudflare 인프라에서 계속 운영됩니다.
  • URL 의존성으로 출발한 Deno는 deps.ts, lock.json, import maps를 거쳐 결국 매니페스트와 잠금 파일을 다시 만들었고, Bun이 등장한 뒤 npm 호환으로 돌아섰습니다.
  • Yarn의 잠금 파일, pnpm의 저장 공간 절약, Bun의 설치 속도가 npm의 기본값을 바꿨고, 설치 스크립트를 기본으로 실행하지 않는 변경도 npm 12에 예고돼 있습니다.

04Linux 7.2 개발 통계 - 기여자 2,652명으로 역대 최다, LLM 지원 패치도 증가

Linux 7.2는 병합을 제외한 커밋 16,418개로 커널 역사상 두 번째로 활발한 개발 주기였습니다. 참여 개발자 2,652명과 첫 기여자 613명은 둘 다 역대 최다입니다. LLM 지원을 표시하는 Assisted-by 태그는 301개에서 1,111개로 늘었지만, 실제로 LLM을 쓴 규모는 이보다 훨씬 클 것으로 봅니다.

  • 태그를 아예 넣지 않는 개발자가 많고, 패치를 적용하면서 태그를 지우는 메인테이너도 적어도 한 명 있어서 LLM 지원 커밋을 정확히 추적하기는 어려울 수 있습니다.
  • LLM 기반 검토 시스템 Sashiko에 버그 발견 공을 돌린 Reported-by 태그가 252개였고, 이전 버그를 고쳤다는 Fixes 태그가 붙은 커밋은 4,830개로 급증했습니다.
  • LLM이 기여의 문턱을 낮추고 버그 탐색을 돕는 건 분명하지만, 제출한 사람도 다 이해하지 못한 코드가 쌓일 수 있다는 점은 아직 판단하기 이릅니다.

06CVE-2026-99999(PwnEscape) — Linux 커널 취약점으로 VM 탈출 가능, VPS 사업자 긴급 대응

Vercel이 연 100만 달러 규모의 Sandbox 해킹 챌린지에서 Linux 커널의 치명적인 취약점이 나왔고, CVE-2026-99999(PwnEscape)로 등록됐습니다. 호스트 커널의 IPv4 처리 경로가 checksum_start 메타데이터를 검증하지 않아서, VM 안에서 조작한 패킷이 호스트의 메모리를 망가뜨릴 수 있습니다. 게스트 커널을 업데이트하는 것만으로는 막을 수 없습니다.

  • Vercel 운영 환경에서는 호스트 메모리 유출이 재현됐고, 호스트 크래시와 관리자 권한 코드 실행은 연구자의 KVM·Firecracker 테스트 환경에서 재현됐습니다.
  • 사쿠라 인터넷은 10월 16일부터 모든 리전에서 신규 VPS 신청과 스케일업을 멈췄고, AWS는 EC2·Lambda·Fargate가 영향을 받지 않는다고 공지했습니다.
  • 하이퍼바이저가 아니라 호스트가 VM과 함께 쓰는 네트워크 스택(virtio-net/TAP)에서 격리가 뚫렸다는 점이 이번 사례의 핵심입니다.
