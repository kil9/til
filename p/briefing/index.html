01chrome-capture - Chrome 탭의 화면과 소리를 최대 4K 120fps로 녹화하는 도구

URL과 녹화 시간만 주면 Chrome 탭의 화면과 소리를 AV1 MP4로 저장합니다. Chrome 153에 들어간 내장 녹화 API를 쓰기 때문에 브라우저가 녹화하면서 바로 인코딩하고, FFmpeg는 따로 설치하지 않아도 됩니다. 기본값은 720p 60fps이고 최대 4K 120fps까지 올릴 수 있습니다.

  • 녹화 시작과 종료는 Playwright, Puppeteer, CDP에서 제어할 수 있어서, 로그인이나 페이지 로딩을 마친 뒤 필요한 구간만 찍을 수 있습니다. 마우스 커서와 클릭 위치도 화면에 표시할 수 있습니다.
  • Playwright 테스트의 녹화 영상은 테스트 리포트에 자동으로 붙습니다. M4 Max에서 같은 6.4초짜리 UI 조작을 녹화했을 때, 녹화가 끝난 뒤 파일을 마무리하는 데 걸린 시간이 기존 Playwright 방식의 3.8초에서 17ms로 줄었습니다.
  • Chrome/Chromium 153 이상과 Node.js 24.11 이상이 필요하고, 라이선스는 Apache-2.0입니다.

02더 많은 앱이 아니라 더 나은 오픈소스가 필요하다

AI 보조 코딩으로 주말에 습관 추적기나 메모 앱을 만드는 것도 좋지만, 그 힘의 일부는 이미 많은 사람이 쓰는 오픈소스를 고치는 데 쓰였으면 합니다. 비영리단체의 서비스를 직접 호스팅해 보면 소프트웨어 자체보다 운영이 어려운 경우가 더 많았습니다. 수백만 명이 쓰는 도구를 20% 가볍게 만들면 모든 사용자가 매일 덕을 봅니다.

  • 주말을 들일 만한 개선은 네 가지입니다. 느린 곳을 재서 빠르게 하기, 명령어 하나로 설치되게 하기, 안전한 업그레이드와 다음 조치를 알려 주는 오류 메시지로 운영을 편하게 하기, 5달러 서버나 Raspberry Pi에서도 돌아가게 가볍게 하기.
  • 기여할 때는 도구를 먼저 직접 써 보고, 코드를 쓰기 전에 유지관리자와 이야기하고, '빨라졌다' 대신 측정 수치를 가져와야 합니다. 변경은 작게 유지하고, AI를 썼다면 밝히고, 문제가 생기면 남아서 고칩니다.

  • 같은 모델이라도 하네스에 따라 작업당 비용이 1.8-5.0배 차이 났고, 비싼 하네스가 통과율을 보장하지는 않았습니다. 실행 단계가 많을수록 매번 전체 문맥을 다시 보내므로, 초기 프롬프트가 작다고 싸지는 않았습니다.

04MAI Code 2와 Code 2 Flash - 일상적인 기업 코딩의 가격 대비 성능에 초점을 맞춘 모델

05Nginx HTTP/2 에서 인증 없이 원격 코드 실행 취약점

  • 댓글 472개의 첫 반응은 '야생에서 악용되기까지 몇 시간이나 걸릴까'였습니다. 블로그에 공개된 세부가 꽤 자세하다는 이유입니다.
  • 한 댓글은 처음에 패치 버전이 안 보인다며 공개 시점을 문제 삼았지만, 30분 안에 새 버전이 나왔다고 정정했습니다.
