01AI에 회사 맥락을 제공하고 ‘회사 두뇌’를 구축하는 방법

AI가 회사에 맞는 답을 하려면 지표 정의, 승인 기준, 내부 용어처럼 추측할 수 없는 것을 적어 줘야 합니다. 저희는 직원과 AI 에이전트가 함께 쓰는 그 기록을 '회사 두뇌'라고 부릅니다. 1-2쪽짜리 문서와 업무 도구 2-3개 연결부터 시작하길 권합니다.

  • 신입이 첫 주에 물을 내용을 기준으로 삼습니다. 회사 개요, 용어집, 지표 계산식과 원천 시스템, 고객군 기준, 정책, 업무 방식, 문체를 문서 하나에 담고, 가격이나 직원 수처럼 바뀌는 값에는 날짜를 붙입니다.
  • 바뀌는 사내 지식은 파인튜닝이 아니라 검색과 최신 기록 조회로 줍니다. 파인튜닝은 형식과 문체를 맞추는 데 씁니다. 커넥터와 MCP 는 최신 기록을 가져오는 대신 기존의 과도한 공유 권한까지 물려받는다는 점을 먼저 확인해야 합니다.
  • 답을 아는 질문 10-20개를 만들어 두고 문서나 연결 도구가 바뀔 때마다 답과 출처를 확인합니다. 문서마다 담당자와 검토일을 정해야 개인 채팅에 갇힌 지식이 퇴사 뒤에도 조직에 남습니다.

02나는 AI로 인한 두뇌 과부하에 이렇게 대처한다

04LLM 시대의 확장 가능한 소프트웨어

LLM이 확장 코드를 쓸 수 있게 됐고 샌드박스도 충분히 싸졌습니다. 그렇다면 웹 앱은 안정적인 코어만 지키고, 사용자마다 다른 롱테일 요구는 사용자가 말로 만든 확장으로 채울 수 있습니다.

  • 모든 기능을 제품에 넣으면 UI가 무거워지고, 소수가 원하는 기능이 나머지 사용자에게는 짐이 됩니다. Pi처럼 도구·명령·이벤트·UI 훅만 안정적으로 열어 두고 확장을 패키지로 공유하는 편이 낫습니다.

05Replit, microVM으로 샌드박스 엔진 재구축

자율 에이전트가 코드를 돌리는 환경을 더 단단히 격리하려고 샌드박스 엔진을 처음부터 다시 만들었습니다. 수억 개 프로젝트를 데이터 손실과 서비스 중단 없이 옮겼고, 새 시스템은 수개월째 프로덕션에서 안정적으로 돌고 있습니다.

  • 예전에는 샌드박스들이 호스트의 Linux 커널을 공유했습니다. 이제는 Cloud Hypervisor 기반 microVM마다 자체 커널이 있어서, 게스트 커널이 뚫려도 호스트에 닿으려면 가상화 경계를 한 번 더 넘어야 합니다.
  • VM 안에서는 runc 컨테이너별로 권한을 나누고, eBPF로 프로세스·파일·네트워크 활동을 보며 Linux 보안 모듈로 금지 동작을 막습니다. 외부 통신 규칙과 자격 증명은 VM 밖에서 관리하므로 샌드박스에 API 키를 넘기지 않고, npm·pip의 알려진 악성 패키지도 막습니다.
  • 미리 띄워 둔 웜 풀 VM에 고객 디스크를 핫플러그로 붙여 약 500ms에 샌드박스를 내줍니다. 파일시스템 데이터는 원격 스토리지에서 필요한 만큼만 읽어 옵니다.

06소스는 공개하되, 외부 기여는 받지 않는다

LLM으로 코드를 만드는 비용은 거의 사라졌지만 검증 비용은 그대로입니다. 그래서 외부 패치를 읽고 검토하느니 유지관리자가 직접 고치는 편이 싸집니다. SQLite처럼 소스는 공개하되 코드 기여는 받지 않는 방식이 퍼질 거라고 봅니다.

  • 코드를 지키던 해자는 라이선스가 아니라 재구현 비용이었고, 그 장벽이 사라졌습니다. BSL·SSPL 같은 절충도, 카피레프트의 협상력도 재구현이 비쌀 때만 통합니다.
  • 조직마다 필요한 기능은 내부로 들어가고, 프로토콜·파일 형식·암호 라이브러리처럼 호환성이 곧 가치인 최소 코어만 공유로 남을 겁니다.
  • 그 코어의 상품은 코드가 아니라 검증 가능한 명세와 테스트입니다. 여러 모델은 학습 말뭉치와 사각지대를 공유하므로 서로를 독립적으로 검증해 주지 못합니다.

07[AI 코딩] 클로드 코드 테스트 게이트 exit 1 대 2, 통과한 쪽과 막은 쪽은 무엇이 달랐을까

Claude Code 훅 검사기가 '막음'을 찍고 exit 1로 끝나면 막힐까요? 아니었습니다. PreToolUse(Write) 훅이 exit 1일 때 모델은 완료했다고 답했고 파일도 그대로 만들어졌습니다. 같은 스크립트의 마지막 숫자만 2로 바꾸자 Write가 차단됐습니다.

  • 공식 훅 문서도 'Exit 2 means a blocking error'라고 적고 있습니다. 훅에서 exit 1은 막는 신호가 아니라 흘려보내는 오류일 뿐입니다.
  • 셸에서는 반대로 0이 아닌 코드가 전부 막았습니다. 그런데 검사 출력을 남기려고 | tee gate.log를 붙인 줄에서는 검사기의 1이 파이프 끝 tee의 0에 덮여 다음 단계가 실행됐습니다.
  • 그래서 검사기는 0 통과, 1 막음, 2 판정 불가로 고정했습니다. 셸에는 set -o pipefail을 켜고, 훅에서는 막을 경우를 전부 exit 2로 냅니다. 확인한 것은 Claude Code 2.1.281, haiku, PreToolUse(Write) 한 번씩뿐이라 다른 훅 이벤트는 모릅니다.
