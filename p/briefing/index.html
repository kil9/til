01JVM 시작 시간, 330초에서 3초로 줄이기

파드 하나가 트래픽을 받을 수 있게 되기까지 330초가 걸렸고, 그중 245초가 JIT 워밍업이었습니다. 그래서 부팅을 빠르게 만들기보다 부팅을 되풀이하지 않기로 했습니다. CRaC으로 워밍업을 마친 JVM을 저장해 두었다가, 새 파드에서는 2-3초 만에 복원합니다.

  • 전체 배포는 20분에서 4분으로 줄었고, 정상 상태 파드 CPU는 예전의 20% 수준이 됐습니다. 그동안 쓸모가 없던 오토스케일링과 스팟 인스턴스도 이제 쓸 수 있습니다.
  • 적용한 날 여러 파드가 cpu.features 불일치로 시작을 거부해서 CRaC 이전 이미지로 롤백했습니다. 같은 AWS 인스턴스 유형 안에서도 하드웨어 세대가 섞일 수 있었고, 그래서 체크포인트를 만들 때 기준 CPU 기능 집합을 고정했습니다.
  • GraalVM 네이티브 이미지를 쓰려면 코드를 많이 고쳐야 하고 JIT 최대 처리량도 포기해야 했습니다. AppCDS는 클래스 로딩만 빨라질 뿐 워밍업 비용에는 손을 대지 못했습니다.

  • 결과의 주도권을 쥔 채 일을 넘기는 인지적 위임과, AI의 출력이 어느새 내 생각이 되어 버리는 인지적 항복은 다릅니다. 에이전트의 도움을 받고도 결과를 설명하지 못한다면 이미 주도권을 넘긴 것입니다.

05NIKKE PC 런처 침해 사고

2026년 9월 27일부터 Level Infinite가 운영하는 CDN의 공식 JavaScript 파일 4개에 공격 코드가 들어 있었습니다. 변조된 파일을 받은 NIKKE PC 런처는 외부 로더를 불러오고, 런처 자체의 JS 브리지로 LuaJIT 원격 제어 에이전트를 내려받아 실행했습니다.

  • 에이전트는 임의 명령 실행, 파일 수집, 화면 캡처, 브라우저 비밀번호와 세션, SSH 키, 클라우드 토큰, 암호화폐 지갑 수집이 가능했습니다. Windows에서는 Chrome 경로에 DLL을 심어 지속성까지 확보했습니다.
  • Proton으로 런처를 돌린 Linux·Steam Deck도 영향 범위에 들어갑니다. 피해자마다 크기는 같고 내용이 다른 빌드가 나와서, SHA-256 하나로는 감염을 다 잡을 수 없습니다.
  • 11월 3일에 파일을 교체했지만 일부 엣지는 옛 사본을 계속 내보냈습니다. 런처 캐시를 지워도 이미 설치된 지속성이나 유출된 자격 증명은 되돌릴 수 없습니다.
