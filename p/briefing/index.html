01당신이 안 보는 사이 프론트엔드에 무슨 일이 있었나

  • jQuery가 없앤 브라우저 차이 대신 데이터가 JS 변수와 화면 양쪽에 존재하는 수동 동기화 문제가 남았고, 이후 모든 레이어가 이 원죄를 갚으려 애씁니다.

07왜 LangGraph 도입 후 코드가 더 복잡해졌나 — 실패에서 배운 기록

상태 관리와 흐름 제어가 깔끔해질 거라 기대하고 LangGraph를 도입했는데 코드가 더 복잡해졌습니다. 프레임워크를 넣고도 구조가 나빠질 수 있다는 걸 직접 겪었고, '어떻게 쓰는가'가 아니라 '어떻게 잘못 썼는가'를 남깁니다.

  • 노드가 하나뿐인 current_step → END 구조라 graph.invoke()가 함수 직접 호출과 다를 게 없었고, step 전환 판단은 그래프 밖 서비스 코드가 하고 있었습니다.
  • MemorySaver와 자체 PostgreSQL Checkpointer가 같은 세션을 이중으로 저장·복원해 불일치가 났고, 8,700줄쯤 되는 Executor 3개에서 핵심은 LLM 호출과 프롬프트 조립 정도이며 나머지는 상태 관리와 에지케이스 패치였습니다.
  • 진짜 원인은 바이브 코딩 자체가 아니라 검증 없는 진행이었습니다. 프레임워크가 무엇을 책임지도록 설계됐는지 모른 채 그 위에서 지시만 내린 상태였고, 독립 토폴로지와 thread_id 격리, State에는 메타데이터만 두고 본문은 Store로, 네이티브 tool_use, 노드 분리로 되돌렸습니다.

08AI 에이전트 여러 개를 한 레포에 풀어놨더니 생긴 일

에이전트 세션 여러 개를 한 레포에 풀어놨더니 일주일 만에 브랜치 탈취, 고아 커밋, 스테이징 오염, 이중 구현이 다 터졌습니다. HEAD는 결국 모두가 공유하는 전역 변수더군요. 데이터베이스에서 배운 동시성 문제가 작업 디렉터리에서 그대로 재연된 이야기입니다.
