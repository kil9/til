01시스템 프로그래밍에서 C보다 Zig를 선택하는 이유

C는 여전히 제가 가장 좋아하는 언어지만, 새 코드를 쓸 때는 Zig를 고릅니다. 둘 다 가비지 컬렉터 없이 기계에 가깝게 쓰는 작은 언어인데, C에서 사람이 시간을 들여 챙기던 자원 정리와 오류 처리를 Zig는 언어 기능으로 맡아 줍니다. 기존 C 코드와 한 프로젝트에서 같이 빌드되니 파일 단위로 옮겨 갈 수도 있습니다.

  • errdefer는 정리 코드를 할당 바로 아래에 두고 오류가 났을 때만 역순으로 실행합니다. FailingAllocator로 할당 실패 경로를 하나씩 일으켜 누수까지 테스트할 수 있습니다.
  • 배열 끝을 한 칸 넘겨 읽는 예제에서 C는 경고 없이 sum = 7을 냈지만, Zig 슬라이스는 길이를 알기 때문에 Debug와 ReleaseSafe에서 바로 멈췄습니다. 정수 오버플로도 같은 방식으로 잡습니다.
  • 다만 Zig도 해제한 메모리에 다시 접근하는 오류는 막지 못하고, 버전 간 호환성과 지원 도구 범위는 C에 못 미칩니다. HN 댓글에서는 새니타이저, [[nodiscard]], span 타입을 쓰면 현대 C로도 대부분 얻을 수 있다는 반론이 나왔습니다.

02Edge0-145B - 개인 컴퓨터에서 실행하는 1,450억 매개변수 AI 모델

Edge0-145B와 120B의 가중치를 추론 엔진, 배포 도구와 함께 공개합니다. 1,450억 매개변수 모델을 NVIDIA GPU 한 장이 달린 PC나 메모리 29GB 노트북에서 서버 없이 돌리는 것이 목표였고, 이를 위해 모델과 엔진을 처음부터 같이 설계했습니다.

  • 전문가 64개가 큰 행렬 두 개를 공유하고 차이분만 따로 들고 있어서 단계마다 실제로 계산하는 매개변수는 약 10B입니다. 핫 전문가는 GPU에, 약 40GB 전문가 라이브러리는 시스템 메모리에, 약 48GB 어휘 데이터는 SSD에 둡니다.
  • 자체 측정으로 RTX 5090 D 24GB에서 초당 약 100토큰, Terminal-Bench 2.1 86.52%, DeepSWE 1.1 64.6%가 나왔습니다. 같은 Terminal-Bench에서 Claude Opus 4.6(Max)은 78.2%였습니다.

03Ace - 내 Mac에서 팀원과 AI 에이전트가 함께 작업하는 코딩 환경

채널에서 팀원과 구현 방향을 이야기하다가 @ace를 부르면, 에이전트가 앞선 대화를 읽고 바로 작업을 시작합니다. 에이전트는 채널 주인의 Mac에 설치된 Xcode, Docker, gh를 그대로 쓰고, 같은 Tailscale 네트워크의 팀원이 들어와 진행 상황을 보거나 직접 작업을 맡길 수 있습니다.

  • 작업마다 Git worktree와 브랜치를 따로 만들어 병렬로 진행하고, 변경 사항은 채널에서 검토해 PR로 엽니다. GitHub 이슈나 기존 PR을 채널로 불러와 이어 갈 수도 있습니다.

04Foundation Models framework - 온디바이스와 클라우드 LLM을 통합하는 Swift API

Foundation Models framework는 Apple 온디바이스 모델, Private Cloud Compute 모델, Claude, Gemini를 같은 Swift API로 부를 수 있게 합니다. 구조화된 응답 생성과 도구 호출, 이미지가 들어간 프롬프트를 지원하고, Vision의 OCR과 바코드 읽기는 기기에서 처리합니다.

  • Dynamic Profiles를 쓰면 대화 기록은 그대로 두고 모델, 도구, 지침만 바꿀 수 있습니다. 간단한 분석은 온디바이스 모델에, 깊은 추론은 클라우드 모델에 맡기는 식입니다.

06Claude Fable 5.2로 에이전트 1,000개 팀 안전하게 돌리기 - 페르마의 마지막 정리 형식화 실험

출시 전 Claude Fable 5.2로 리드 에이전트 1개와 헬퍼 999개를 돌려 페르마의 마지막 정리 증명을 Lean으로 형식화했고, 28.7시간이 걸렸습니다. 9월에 에이전트 수십 개와 연구자 지휘로 11일 걸렸던 실험에 비해 출력 토큰은 1/3, 증명 길이는 1/7로 줄었습니다.

  • 협업 도구는 따로 두지 않았습니다. 에이전트별 Git 브랜치와 공유 Postgres뿐이었고, 리드가 첫 10분 안에 Announce, Assign, Notes, Subtasks, Landed 표 다섯 개를 만들었습니다. 가장 어려운 Langlands–Tunnell에는 헬퍼 약 750개가 붙어 작업 2,418개로 쪼갰습니다.

08비싼 Raspberry Pi 대신 집에 있는 헌 폰을 쓰는 이유

Why get an expensive Pi when I have an old phone?

  • Pi의 핵심은 GPIO라 소프트웨어만 돌릴 거면 폰도 Pi도 아닌 ITX 보드가 낫다는 반론이 맨 위에 올라왔습니다.
