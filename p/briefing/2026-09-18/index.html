01LLM 시대의 프로그래밍 학습

한 독자가 편지를 보내왔습니다. 정규 전산 교육 없이 1년간 LLM으로 API와 PostgreSQL, LLM 파이프라인이 얽힌 시스템을 만들었는데, 제품화 단계에서 자기가 이해하지 못하는 동작과 연쇄 오류에 부딪혔다고요. 작동하는 제품을 만든 것인지, 책임질 수 없는 제품의 외형을 만든 것인지 모르겠다는 물음에 답을 적어 봅니다. 확실한 답은 아니고, 지금 상황 자체가 확실하지 않습니다.

  • 개발자는 원래부터 완전히 이해하지 못하는 추상화 위에서 일해 왔습니다. 웹 개발자가 컴파일러를 다 아는 것도, 컴파일러 개발자가 집적회로 설계를 아는 것도 아닙니다. 제 경험칙은 지금 일하는 계층의 바로 위와 아래를 이해하는 것이고, 그것으로 대부분의 문제를 풀었습니다.
  • 저는 1999년에 내부 동작을 거의 모른 채 C++로 COM 컴포넌트를 썼고, 만족하지 못해 한발 물러나 기초를 공부했습니다. 1990년대 중반에 시작한 경력에는 그 방식이 맞았지만, 지금 입문하는 사람에게 수십 년이 남아 있는지는 모르겠습니다.
  • LLM에는 "다음에 뭘 배울까"보다 "이 코드를 더 짧게 만들 수 있나"처럼 답을 직접 검증할 수 있는 질문을 던집니다. 실제로 돌아가고 짧아졌는지 제 눈으로 확인할 수 있으니까요.
  • AI가 가장 잘할 때 가장 강한 반감이 듭니다. 저는 나이와 그간의 성취 덕에 실업을 견디겠지만, 30-40% 규모의 실업을 지식 사회 전체가 견딜 수 있을지는 다른 문제입니다. 기술이 새 일자리를 만들었다는 역사는 그 일자리가 잃은 사람에게 갔다는 뜻이 아닙니다.

02작은 프로그래밍 요령들

엔지니어링 생산성의 상당 부분은 거창한 것이 아니라 작은 지식에서 나옵니다. 언어에 그런 기능이 있다는 사실, 원인 모를 TCP 지연이 Nagle 알고리듬과 관련 있을 수 있다는 감, 곤란한 상황을 빠져나오는 git 명령 하나 같은 것들이요. 특히 사전 지식이 거의 없어도 바로 쓸 수 있는 요령이 값집니다.

  • Python을 몰라도 `python3 -m http.server` 로 현재 디렉터리를 서버로 띄울 수 있습니다. 검색은 대체로 grep·ack·ag보다 rg를 권하고, find는 `**/*.md` 같은 글롭으로 대체되는 경우가 많습니다(Bash는 `shopt -s globstar` 가 필요합니다).
  • 명령 이력은 fzf로 ctrl+r 퍼지 검색을 붙이거나, atuin으로 검색 가능한 SQLite로 통째로 바꾸거나, per-directory-history로 디렉터리별 이력과 전체 이력을 오갈 수 있습니다.
  • `git log -S pattern`(git pickaxe)은 특정 문자열을 넣거나 뺀 커밋을 찾아 주고, `-G` 는 그 줄이 이동한 경우까지 보여 줍니다. `git checkout -` 는 `cd -` 처럼 직전 HEAD로 돌아갑니다.
  • 회사 안에도 짧게 전할 수 있지만 효과가 큰 지식이 있습니다. 어느 데이터 소스를 볼지, 누가 그 분야에 밝은지, 롤링 재시작 명령이 무엇인지 같은 것들요. 이전 회사에서 매일 Slack에 요령 하나씩 올린 방식은 열에 아홉을 이미 알더라도 나머지 하나가 시간을 아껴 줬습니다.

03발표가 좋았다면 발표자에게 말해주세요

발표가 좋았다면 발표자에게 직접 말해 주세요. 발표자는 준비에 많은 시간을 들이고, 청중이 즐겼는지 자기가 잘했는지 알고 싶어 합니다. 반응이 하나도 없는 침묵은 생각보다 오래 남습니다.

  • 저는 비교적 최근에 컨퍼런스 발표를 시작해서, Twitter가 망가지기 전 발표자들이 받았다는 대량의 피드백은 겪어 보지 못했습니다. 발표 뒤 온라인 반응이 전혀 없던 행사에서는 청중에게 닿지 않았는지, 싫어했는지를 계속 생각하게 됩니다.

06DeepSeek V4.1 Flash, 이제 Enclave의 최고 해킹 모델

DeepSeek V4.1 Flash가 저희 해킹 벤치마크의 취약 타깃 11개 전부에서 코드 실행에 성공했고, 수정된 대조군 4개는 모두 안전하게 유지됐습니다. 다만 전체 공격 경로를 감사해 보니 의도한 취약점을 이용한 것은 6회고 나머지 5회는 테스트 환경의 예상 밖 경로였습니다.

  • 전체 벤치마크에서 Bash 명령 2,349개를 썼고 실제 작업 시간은 약 2시간 38분, 성공 실행의 소요 시간 중앙값은 4분 38초였습니다. 입력 토큰 2억 6,830만 개 중 2억 6,620만 개가 캐시되어 성공 실행 비용은 4.65달러에 그쳤습니다.
