01개발 블로그 글쓰기의 안티패턴

개발 블로그에서 가장 흔한 실수는 본론까지 너무 오래 걸리는 겁니다. 제목과 첫 세 문장 안에 이 글이 누구를 위한 것인지, 읽으면 무엇을 얻는지 답해야 합니다. 독자는 다른 글을 얼마든지 고를 수 있으니까요.

  • 독자가 나만큼 안다고 가정하지 마세요. 실제 친구나 동료 한 명을 기준 독자로 정하고, 그 사람이 아는 용어와 모르는 용어를 목록으로 만들어 초안과 대조하면 됩니다.
  • 생소한 용어에 링크만 걸거나 이전 편을 읽고 오라고 하지 말고, 이 글만으로 이해할 최소한의 설명을 본문에 넣으세요. 링크는 필수가 아니라 추가 자료여야 합니다.
  • 격식 대신 평소 말투로 쓰고, 게시 전에는 모바일에서 본문이 화면을 넘치지 않는지 확인하세요. 댓글에서는 작성일을 맨 위에 두지 않는 것과 꼭 읽어야 하는 내용을 각주에 넣는 것이 안티패턴으로 덧붙었습니다.

02D2Coding 폰트 1.4.0 공개 - 숫자 0 선택 기능과 한글/코드 표시 개선

코딩 글꼴 D2Coding 1.4.0 을 공개합니다. 한글·영문·숫자·기호가 섞인 코드의 가독성과 정렬을 다듬었고, 빗금 있는 0 대신 가운데 점이 있는 0 을 고를 수 있게 했습니다.

  • 점 있는 0 은 기본 모양을 그대로 두고 OpenType 의 cv01 또는 ss01 로 켭니다. VS Code 에서는 editor.fontLigatures 를 'cv01' 로 설정하면 됩니다.
  • 마침표를 가운데점처럼 보이게 하던 .=, .-, {., .} 리거처를 없앴습니다. Go 템플릿이나 CSS 선택자에서 코드 의미를 잘못 읽지 않도록 원래 문자를 그대로 보여 줍니다.
  • 일부 크기에서 글자가 기준선보다 한 픽셀 떠 보이던 문제와 ☕·⚡ 같은 터미널 기호 20자의 폭을 고쳤습니다. 기존 버전을 지우고 설치한 뒤 에디터와 터미널을 다시 실행해야 적용됩니다.

03SQLite의 확장은 더 큰 DB가 아니라 더 많은 DB

Postgres 하나면 대부분 됩니다. 그런데 사용자마다 작은 데이터를 따로 두거나 잠깐 쓸 프로그램에 DB를 붙일 때도 같은 구성이 필요할까요. 요즘 SQLite 의 확장은 DB 하나를 키우기보다 작은 DB를 필요한 곳마다 가볍게 나눠 주는 쪽으로 가고 있습니다.

  • 먼저 채워진 건 새 SQL 문법이 아니라 Litestream·LiteFS 같은 백업·복제 도구였습니다. 다만 백업이 있다고 다른 서버가 곧바로 쓰기를 넘겨받는 건 아니고, 읽기 복제본이 늘 최신인 것도 아닙니다.
  • lobste.rs 는 MariaDB 에서 SQLite 로 옮기다 한 번 롤백했지만 쿼리를 고친 뒤 다시 전환해 CPU 와 메모리를 줄였습니다. Julia Evans 는 ANALYZE 한 번으로 FTS5 검색을 5초에서 0.05초로 줄였고, 대량 삭제는 작은 배치로 나눠야 했습니다. DB 서버를 없애도 DB 운영 지식은 남습니다.
  • Poke 는 AI 가 만든 웹사이트마다 Turso DB 를 하나씩 붙여 약 1만 개를 만들었고, 10월 2일에는 Postgres 중심으로 커 온 Supabase 가 Turso 인수를 발표했습니다.

07Codemode란 무엇인가 - AI의 도구 호출을 코드로 묶기

  • Codemode 는 작업 대상 환경이 아니라 하네스 쪽 샌드박스에서 돕니다. Pi 는 WASM 런타임 안의 QuickJS 를 쓰고 네트워크·파일 시스템·타이머에 직접 닿지 못하게 막아 둡니다.
