02타임스탬프를 시·분·초로 변환하는 더 빠른 방법

요일 계산을 빠르게 만드는 글의 후속으로, 하루 안의 초 [0..86399]를 시·분·초로 쪼개는 계산을 다룹니다. 주요 날짜/시간 라이브러리는 앞 계산 결과를 차례로 기다리는 구조라, 비트 기법을 꺼내기 전에 계산 순서만 바꿔도 대기 시간이 크게 줄어듭니다. 글을 쓰기 시작하고서야 함수 구조 변경이 속도 향상의 가장 큰 원인이었고 기존 라이브러리들이 대체로 놓친 접근이었다는 걸 알았습니다.

  • 전통적 방식 1(Linux 커널·glibc·Go·CPython·OpenJDK)은 초가 분에, 분이 나머지에, 나머지가 시에 의존해 근사 16사이클, 방식 2(V8·Boost·musl)는 12사이클입니다.
  • V1은 전체 분과 시간을 먼저 독립적으로 구한 뒤 초와 분을 병렬로 계산해 복잡한 비트 기법 없이 8사이클로 내려갑니다. 핵심은 분을 원래 입력이 아니라 두 중간 결과로 구하는 것입니다.
  • V2는 고정소수점 곱셈의 상·하위 비트를 함께 써 약 6사이클, V3는 60진법을 64진법 나머지 연산으로 바꿔 일부 대상에서 5사이클까지 갑니다.
  • 컴파일러가 알아서 재배열해 주기를 기대하지 마십시오. .NET JIT과 MSVC는 인식하지 못했고 Clang과 GCC는 %를 뺄셈·곱셈으로 바꿨을 때만 인식했습니다.

  • 항상 필요한 규칙만 AGENTS.md에 짧게 두고 긴 절차는 필요할 때 읽을 스킬로 빼되, 본문을 안 읽어도 이름과 설명 목록이 컨텍스트를 먹으므로 설치 수가 늘어나는 문제까지 사라지지는 않습니다.
  • 검증은 성공한 작업을 스킬로 만든 뒤 대화 기록을 비운 새 세션에서 다시 돌려 보는 방식이고, 실패 사례는 회귀 테스트로 남깁니다. 모델이나 실행 환경이 바뀌면 같은 스킬도 다르게 동작합니다.

05Apache Maka - 에이전트가 한 일을 기록으로 남기는 로컬 우선 워크스페이스

원하는 모델을 붙여 데스크톱이나 터미널에서 작업을 맡기고, 에이전트가 무엇을 했는지 실행 과정까지 되짚을 수 있는 작업 공간입니다. 대화만이 아니라 도구 호출과 그 결과, 권한 승인 여부, 종료 상태를 순서대로 남기고 그 기록을 화면 표시와 다음 요청 구성, 비정상 종료 후 복구에 씁니다.

  • 모델에 넘기는 문맥을 줄여도 원래 실행 기록은 보존합니다. 오래된 도구 출력을 다음 요청에서 빼더라도 이력에서 지우지는 않습니다.
  • 데스크톱과 TUI/CLI, 평가 도구가 같은 실행 엔진을 쓰며, 같은 모델과 공식 채점기로 다른 에이전트 도구와 비교한 완료율·비용·개별 실행 기록을 평가 보고서로 공개합니다.
  • 파일 작업과 셸 실행에 권한 확인과 OS 샌드박스를 걸지만 보호 범위는 플랫폼과 설정에 따라 다르고 모든 도구를 격리하지는 않습니다. API 키는 로컬 평문 파일에 두되 저장된 값을 화면 프로세스로 되돌려 주지 않습니다.
