01이딴 짓은 이제 못 해 먹겠다

대기업에 들어온 지 보름 됐는데, 명세도 코드도 테스트도 티켓도 보고서도 전부 Claude Code가 만듭니다. 경영진은 코드 작성이 더는 병목이 아닌데 왜 느리냐고 묻고, 우리는 하루 12-13시간씩 지시하고 엔터를 누릅니다. AI를 쓰는 게 싫은 게 아니라, 만들어진 게 어떻게 도는지 확인할 시간조차 없다는 게 문제입니다.

  • 동료의 AI가 쓴 요구사항을 내 AI가 고치고 다시 동료의 AI가 검토해서 돌려보냅니다. 사람끼리 대화하는 대신 AI 문서를 나르는 중간 전달자가 된 기분입니다.
  • 생산성 기대는 검토할 여유가 아니라 더 많은 일과 더 적은 사람으로 돌아옵니다. 20명이 넘던 플랫폼 작업을 5명에게 맡긴 인수합병 사례도 댓글에 나왔습니다.
  • 반대편 사례도 있습니다. 모든 코드와 문서를 AI로 만들어도 작업마다 책임자를 두고 무엇을 왜 했는지 설명하게 하는 팀은 사정이 다르다는 이야기입니다.

02Tunnet - 관리 서버까지 직접 운영하는 오픈소스 Tailscale 대안

Tunnet은 Tailscale처럼 여러 장비를 하나의 암호화된 사설망으로 묶습니다. 에이전트만이 아니라 관리 서버, 대시보드, 릴레이까지 공개하므로 외부 업체의 제어 서버 없이 네트워크 전체를 직접 운영할 수 있습니다.

  • 장비마다 사설 IP와 호스트명을 주고 PeerDNS, 서브넷 라우팅, exit node, 공유용 Serve와 공개용 Tunnel까지 한 계정과 정책으로 관리합니다.
  • SSH 키를 장비마다 뿌리지 않고 계정과 접근 정책으로 SSH를 통제하며, Node.js, Bun, Rust 앱에 메시 노드를 직접 내장할 수 있습니다.
  • 라이선스는 구성 요소마다 다릅니다. 에이전트와 SDK는 MPL-2.0, 관리 서버와 대시보드는 AGPL-3.0-only입니다.

03일반 텍스트 파일이 위기에 처해 있다

일반 텍스트 파일은 특정 앱이나 클라우드 없이 기본 편집기로 읽고 고칠 수 있는 가장 범용적인 데이터 형식입니다. 일반 사용자는 스마트폰으로 넘어가며 이미 파일을 잊었고, 마지막으로 남은 개발자마저 LLM REPL에 입력하고 웹에서 diff만 보기 시작했습니다. 편집기를 여는 사람이 사라지면 편집기를 고치는 사람도 사라집니다.

  • 운영체제와 라이브러리는 계속 바뀌므로 유지보수가 끊긴 편집기와 파일 관리자는 어느 순간 돌아가지 않게 될 수 있습니다.
  • 잃는 것은 옛날식 편집 습관이 아니라, 플랫폼이 정한 방식 밖에서 자기 데이터를 직접 읽고 고칠 자유입니다.
  • Lobste.rs에서는 vi 구현은 2,000줄이면 되고 BSD가 계속 유지할 것이라는 반론과, 모두가 LLM으로만 파일을 다루는 미래가 터무니없지 않다는 반응이 갈렸습니다.

06Show GN: FiTuna - llama.cpp 양자화·GPU 오프로드 설정을 추정이 아닌 실측으로 찾는 CLI

llama.cpp를 돌릴 때 양자화 레벨, -ngl, 컨텍스트 길이를 대부분 감으로 고르거나 일단 Q8_0으로 시작합니다. 저도 그랬고 확인할 방법이 없어서 FiTuna를 만들었습니다. 목표 tok/s와 허용 품질손실을 주면 후보를 전부 실제로 양자화하고, perplexity를 재고, 목표를 넘는 최소 -ngl을 이진 탐색합니다.

  • M3 Pro에서 Qwen3-4B, SmolLM2-135M, Midm-2.0-Mini 세 모델 모두 통념상의 Q8_0이 목표 속도를 못 맞췄고, Q4_K_M이나 Q6_K가 통과했습니다.
  • Q4_K_M이 Q6_K보다 느리게 나온 것, Q8_0 perplexity가 Q6_K보다 나쁜 것 두 건은 재현되지만 설명하지 못했습니다. 측정값은 docs/RESULTS.md에 그대로 뒀습니다.
