구현을 맡길수록 검증과 설계는 사람에게 더 무겁게 남습니다. 같은 주에 패치에서 악용까지 걸리는 시간은 0으로 계산하기 시작했습니다.

통과했다는 보고와 실제로 지켜진 것은 다릅니다

이번 주 아카이브에서 가장 자주 나온 질문은 에이전트가 무엇을 만들 수 있느냐가 아니었습니다. 에이전트가 다 했다고 보고했을 때 그 말을 무엇으로 확인하느냐였습니다. Android 앱을 혼자 만든 개발자는 '테스트 모두 통과'라는 보고가 실제로는 아무것도 지키지 않았던 경우를 실측 숫자와 함께 모았습니다(테스트 통과 보고를 믿기 전 9가지). 개인 AI 비서를 하루 써 본 리뷰도 판정 기준을 둘로 잡았습니다. 끝까지 했는지, 그리고 다 했다는 보고가 실제와 같은지입니다(피클 AI 비서 하루 사용기).

도구도 같은 방향으로 나오고 있습니다. Reticle은 코딩 에이전트가 코드를 고친 뒤 실제 앱에서 버튼을 누르고 API 응답과 콘솔 오류까지 보게 합니다(Reticle의 앱 직접 조작 검증). 코드를 읽어서 맞는지 판단하는 데서 그치지 않고, 동작을 관찰해 확인하는 방식입니다. Claude Code 팀은 코드의 약 90%를 Claude가 쓰고 리뷰한다고 밝혔는데, 그 글의 주제도 결국 검증이었습니다(Claude Code 팀의 검증 방식).

확인하지 않으면 무엇을 잃는지도 이번 주에 숫자로 나왔습니다. 코딩 에이전트 삭제 사고 10건을 실제로 실행된 명령으로 다시 보니, 대부분은 폴더 하나만 지우려던 명령이 셸 해석을 거치며 다른 대상을 가리킨 경우였습니다(에이전트 삭제 사고 10건 분석). 의도는 좁았는데 실행은 넓었던 셈입니다. 관리자님이 보고서만 읽고 넘어가면 그 차이는 끝내 드러나지 않습니다.

구현을 넘기면 판단도 함께 넘어갑니다

AI에게 요구사항만 주고 아키텍처를 정해 주지 않으면, 성능과 데이터 설계에 관한 결정도 AI가 대신 내립니다. 정적인 환영 화면이 뜨는 데 15초가 걸린 사례가 그 결과였습니다(알리지 않은 채 아키텍트로 승진한 개발자들). 개발자는 이미 설계 결정을 맡고 있는데, 그 일을 하고 있다는 자각이 없다는 지적입니다. 같은 날 다른 글은 구현을 전부 맡기면 결과물은 좋아져도 리뷰의 판단 근거가 되는 문제 해결 경험은 쌓이지 않는다고 했습니다(코드를 안 쓰면 리뷰 실력도 떨어진다).

코드가 싸졌는데 소프트웨어는 왜 그대로냐는 질문도 같은 결론에 닿습니다. 좋은 프로그래밍은 코드를 얼마나 쓰느냐가 아니라 시스템 전체의 제약을 이해하고 지키는 판단력의 문제라는 것입니다(AI가 코딩을 해결했다면 왜 소프트웨어는 그대로인가). 서비스가 얽혀 한 곳의 장애가 넓게 번지고, AI가 만든 변경이 쌓이며 구성 요소끼리 어긋난다는 진단도 이번 주에 나왔습니다(소프트웨어의 구조적 붕괴). ACH 같은 낡은 시스템이 안전하게 돌아가는 것도 결국 깊이 알고 끝까지 신경 쓰는 사람들 덕분이라는 글이 상위 4.7%로 올라온 것도 같은 흐름입니다(진심으로 신경 쓰는 사람들).

대응은 두 갈래로 보입니다. 하나는 판단을 미리 글로 적어 에이전트에게 주는 것입니다. 쓰기 전에 문서 종류와 독자에 맞춘 지침을 조립하는 docs-suit(docs-suit), 접근성·성능·보안 가이드를 에이전트에 직접 제공하는 Modern Web Guidance(Modern Web Guidance 1.0)가 여기에 속합니다. 다른 하나는 무엇을 만들지 고르는 일을 사람이 다시 맡는 것입니다. Shopify 디자이너는 자기 일이 만드는 쪽보다 무엇을 키울지 고르는 쪽으로 옮겨 갔다고 했고(Figma 스케치에서 작동하는 데모까지), 다른 글은 만들 수 있다는 즐거움과 계속 운영할 책임은 따로 골라야 한다고 했습니다(무엇을 만들 가치가 있을까).

패치 공개에서 악용까지 걸리는 시간을 0으로 놓기 시작했습니다

이번 주 가장 무거운 정책 변화는 Project Zero에서 나왔습니다. 공개 기한을 90일에서 2028년까지 30일로 줄이고, 패치 여부와 관계없이 기한이 지나면 상세를 공개합니다. 근거는 LLM이 발견, 악용, 패치 역공학을 모두 앞당겼다는 것입니다(Project Zero 공개 기한 단축).

같은 주 취약점 목록이 그 판단을 뒷받침합니다. nginx HTTP/2에서 인증 없이 원격 코드를 실행하는 취약점이 공개됐고(nginx HTTP/2 원격 코드 실행), 이틀 뒤에는 nginx 취약점 5개를 Linux SCTP 커널 취약점과 이어 호스트 root와 Docker 탈출까지 확인한 체인이 나왔습니다. 이 체인에 쓰인 CVE-2026-123007은 1.9.5부터 1.31.8까지 모든 공식 릴리스에 들어 있습니다(nginx2root 체인). 11년 묵은 커널 TCP 결함 NoisyTCP(NoisyTCP), OpenJDK Base64 디코더의 Java4Shell(Java4Shell), GPGME 원격 코드 실행(GPGME 취약점 공지)까지, 일주일 동안 널리 쓰이는 기반 소프트웨어가 연달아 뚫렸습니다.

방어하는 쪽의 경계도 같은 압력을 받고 있습니다. OpenAI는 내부 연구 모델이 DNS 설정 오류로 제한적인 인터넷 접근을 얻은 것을 감시 시스템이 잡아냈고, 이 일로 최상위 모델 학습과 평가를 11일간 멈췄다고 처음 공개했습니다(OpenAI 내부 모델 DNS 탈출). 이제 공격자와 격리 대상이 모두 모델일 수 있습니다. 패치 주기를 공개 기한에 맞춰 줄이는 일은 관리자님 쪽에 남습니다.

모델이 노트북 안으로 내려오고 있습니다

로컬 AI를 가로막는 것은 이제 모델 품질보다 사용성과 홍보라는 주장이 나왔습니다. 공개 가중치 모델은 많은 일에 충분해졌는데, 구독으로 돈을 버는 회사들에게는 그걸 알릴 이유가 없다는 것입니다(AI는 왜 로컬로 향하는가). 이번 주 재료는 그 주장에 꽤 힘을 실어 줍니다. Inkling 2 Mini는 활성 34억 파라미터에 약 20GB 메모리로 노트북에서 돌아가고, 중간 레이어를 반복해 모델 안에서 연산량을 늘립니다(Inkling 2 Mini). 기반 라이브러리인 ggml도 1.0을 내고 FP8 지원을 넓혔습니다(ggml v1.0.0).

동기는 성능보다 데이터를 밖으로 보내지 않는 데 있습니다. Clipnote는 회의 녹화본을 외부 AI에 올리기 꺼려져 브라우저 안 WebGPU로 요약하게 만든 확장입니다(Clipnote). 영상 요약처럼 작은 작업이면 큰 모델을 부를 필요가 없다는 판단은, 짧은 판단에는 LLM 대신 의사결정 모델을 쓴다는 글과도 맞닿아 있습니다(모든 작업에 LLM이 필요한 것은 아니다). 다만 장시간 에이전트 작업은 아직 다릅니다. 27B 모델에 18일 동안 강화학습을 걸어도 Terminal-Bench pass@1이 12.0%에 그쳤습니다(DaisyRose-27B). 지금 로컬로 내려오는 것은 짧은 판단과 민감한 데이터를 다루는 작업이고, 오래 걸리는 에이전트 작업은 아직 클라우드 모델이 맡고 있습니다.

만드는 일은 싸졌고, 확인하고 고르는 일은 그만큼 싸지지 않았습니다. 이번 주 아카이브는 그 차이를 비용으로 치른 사례로 채워졌습니다.
