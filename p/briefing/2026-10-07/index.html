03SQLDoom - 오리지널 Doom을 SQL로 포팅하기

1993년 Doom 의 게임 로직과 렌더러를 SQL 로 옮겨 CedarDB 안에서 돌렸습니다. Python 클라이언트는 입력과 타이밍, 완성된 화면 표시만 맡고, 나머지는 전부 데이터베이스 안에서 일어납니다.

  • 몬스터를 하나씩 돌지 않고 조건부 UPDATE 와 조인으로 처리했더니, 원작 C 코드 약 9,000줄짜리 기능이 SQL 약 5,900줄이 됐습니다. 컴포넌트는 테이블로, 시스템은 조인하는 UPDATE 로 옮기면 ECS 가 그대로 관계형 구조에 맞아떨어집니다.
  • 평범한 틱은 평균 2.15ms 였고, 가장 느렸던 틱은 활성 몬스터 46마리가 문으로 몰려온 순간의 10.45ms 로 예산의 37% 정도였습니다.
  • 렌더러는 CTE 89개짜리 거대한 뷰 하나이고, 결과는 64,000개의 (x, y, rgb) 행입니다. 무기 속성도 테이블에 있어서 실행 중에 샷건이 산탄 500개를 쏘게 바꿀 수 있습니다.
