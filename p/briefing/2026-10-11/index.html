01Python 3.15 정식 출시 - 지연 임포트, 불변 딕셔너리, UTF-8 기본 인코딩 도입

Python 3.15.0을 10월 9일 안정판으로 냅니다. 기여자 1,012명이 커밋 5,643개를 보탰고, 이번 판은 시작 시간과 일상적인 코드 작성을 개선하는 데 집중했습니다. lazy import로 모듈 로딩을 처음 쓰는 시점까지 미룰 수 있고, 인코딩을 지정하지 않은 텍스트 입출력은 이제 시스템 환경과 상관없이 UTF-8로 동작합니다.

  • 생성 후 바꿀 수 없는 frozendict, 값이 주어지지 않은 상태 등을 구분하는 sentinel 내장 타입이 새로 들어왔고, [*items for items in lists]처럼 컴프리헨션 안에서 언패킹을 쓸 수 있습니다.

02프로그래밍은 특별하지 않다

프로그래밍도 예술입니다. 기능적인 결과물을 만든다는 이유로, 다른 창작 분야에서는 거부하는 AI 사용을 코드에서만 정당화할 수는 없습니다. 예술도 원래 의뢰를 받아 하는 평범한 노동이고, 광고 문구나 일상적인 코드도 같은 기술과 연습 위에 서 있습니다.

  • Deferred는 RPC를 호출할 때마다 callback과 errback을 넘겨야 하는 지루함과 불편함에서 나왔습니다. 그 지루함을 겪지 않았다면 만들 기술도 동기도 없었을 것이고, 그 흐름은 JavaScript Promises와 async/await까지 이어졌습니다.
  • 추상화와 자동화 자체는 문제가 아닙니다. 문제는 이해와 창의적인 결정을 없애는 쪽이고, 평범한 작업을 통째로 AI에 넘기면 현장에서 솜씨가 늘 기회도, 뛰어난 결과물에 닿을 가능성도 함께 사라집니다.
  • 어디까지 저항할지는 각자 정할 일입니다. 다만 소프트웨어만 예외로 둘 이유는 없습니다.

03DuckLake - SQL과 Parquet 기반의 데이터 레이크하우스 형식

DuckLake는 메타데이터는 SQL 데이터베이스에, 실제 데이터는 Parquet 파일에 두는 개방형 레이크하우스 형식입니다. 전용 카탈로그 서버를 따로 두지 않고 이미 쓰고 있는 데이터베이스를 카탈로그로 씁니다. 이 저장소는 DuckDB에서 그 형식을 직접 읽고 쓰는 확장입니다.

  • 스냅샷과 타임 트래블, 스키마 변경, 지정한 스냅샷 범위의 변경 내역 조회를 지원하고, 여러 테이블에 걸친 작업도 ACID 트랜잭션으로 묶습니다.
  • 로컬 단일 클라이언트는 DuckDB, 여러 로컬 클라이언트는 SQLite, 원격 다중 사용자 환경은 PostgreSQL 카탈로그가 맞습니다. 인증은 카탈로그 데이터베이스의 체계를 그대로 씁니다.
  • HN에서는 DuckLake가 DuckDB 전용이 아니라 명세라는 점이 강조됐습니다. Rust 쪽 datafusion-ducklake 구현자는 Iceberg가 무거웠던 저지연 작업에 써 보니 자체 카탈로그보다 느리지 않았다고 했습니다.

04Windows와 Mac의 키보드 차이 - Ctrl을 Command로 바꾸는 것만으로는 부족하다

같은 코드베이스로 Windows와 Mac을 지원하더라도 Ctrl을 Command로 바꾸는 것만으로는 끝나지 않습니다. 키 이름부터 다르고, Mac에는 Command와 별개로 Control이 있습니다. Option과 AltGr는 다른 언어의 문자를 입력하는 데 쓰입니다.

  • Windows의 Backspace가 Mac에서는 Delete이고 Windows의 Delete는 Mac의 Forward Delete입니다. 플랫폼을 밝히지 않고 'Delete를 누르세요'라고 쓰면 지워지는 방향부터 달라집니다.
  • Option 기반이나 Ctrl+Alt 단축키를 가로채면 폴란드어 ą, ć 같은 필수 문자 입력이 막힐 수 있습니다. Mac 텍스트 필드의 ⌃A, ⌃E, ⌃K 같은 Control 편집 키도 앱이 덮어쓰면 쓸 수 없게 됩니다.
  • Page Up/Down과 Home/End는 Windows에서는 커서를 옮기고 Mac에서는 화면만 스크롤하는 관행이 있습니다. Tab 포커스 이동 범위도 플랫폼마다 다릅니다.
