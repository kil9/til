01오픈 소스에서 월 반복 매출 2만 달러까지: EmailEngine의 여정

Nodemailer는 2011년에 시작했습니다. 오픈소스로 먹고살 방법을 찾으면서 7년 동안 실패를 거듭했습니다. 결국 바꾼 것은 제품이 아니라 과금 방식이었습니다. 라이선스 키가 없으면 돌지 않게 바꾸자 첫 달 매출이 그전 1년 반 동안의 총매출보다 두 배 넘게 많았습니다.

  • AGPL로 공개하고 MIT 라이선스를 따로 팔던 1년 반 동안 유료 고객은 3명, 매출은 750유로가 전부였습니다. 대기업은 대안 라이선스가 있다는 이유만으로 낯선 소프트웨어를 들이지 않았고, 작은 회사는 라이선스에 관심이 없었습니다.
  • 유료 구독이 있어야 쓸 수 있게 바꾼 첫 달에 2,000달러를 벌었고, 모두 무료 IMAP API를 이미 쓰던 회사에서 나왔습니다. 처음부터 기여자에게 CLA를 받아 둔 덕분에 라이선스를 바꿀 수 있었습니다.
  • 구독료를 연 1,450달러까지 올렸지만 신규 고객은 줄지 않았습니다. 지금은 월 반복 매출 2만 달러를 직원도 투자자도 없이 혼자 운영합니다. 다만 실직한 뒤 급여를 빨리 메워야 하는 사람에게 권할 길은 아니라고 봅니다.

02NariQ: BF16 수준의 Qwen3.8-27B를 10GB 파일에 담다

Qwen3.8-27B를 가중치당 3비트·2.5비트·2비트로 양자화해 GGUF로 공개했습니다. 실제 코딩 에이전트 실행 기록으로 양자화 오차를 보정했습니다. 그 결과 10.12GB인 3비트 버전이 DeepSWE 41.0%, Terminal-Bench 63.8%로 BF16(39.8%, 62.6%)과 비슷한 성능을 냅니다.

  • 6.75GB인 2비트 버전은 더 작은 대신 DeepSWE 28.6%, AIME 86.0%로 수학과 에이전트 작업 성능이 확연히 떨어집니다. 기본 권장은 3비트입니다.
  • 새 텐서 타입을 쓰기 때문에 NariQ 전용 llama.cpp 포크에서만 돌고, 기본 llama.cpp·Ollama·LM Studio로는 아직 열 수 없습니다. 포크가 SM120(Blackwell)에 맞춰져 있어 Ampere·Ada·Apple M에서는 비슷한 GGUF보다 느립니다.
  • 파일은 10GB여도 KV 캐시가 BF16이라 24GB GPU에서 3비트 버전의 컨텍스트는 약 135K까지 들어가고, 262K 전체를 쓰려면 32GB 이상이 필요합니다. HN 댓글은 held-out 평가를 밝힌 점을 반겼고, M3 Pro에서는 초당 3-5토큰에 그친다는 보고도 나왔습니다.

huggingface.co · 관심사 상 · 추천 상위 36.6%

03Microsoft, 대규모 장애 이후 ‘Code Red’ 선언…내부 메모로 드러난 대응 문제

11월 12-13일에 24시간 이어진 장애 뒤 Microsoft가 Code Red를 선언했습니다. Exchange Online 역사상 고객 피해가 가장 컸던 사고였고, 원인은 7월에 들어간 뒤 그동안 드러나지 않은 Windows 확장성 결함이었습니다. 내부 메모를 보면 고쳐야 할 것은 결함 하나보다 대응 체계 쪽입니다.

  • 대응 인력은 Teams 채팅방 11개에서 메시지를 1만 1,000건 넘게 주고받았습니다. 그러나 진단 데이터가 여러 추적 시스템에 흩어져 있어 어떤 가설과 결정이 오갔는지 한눈에 보기 어려웠습니다.

09샌드박스에 가둔 모델끼리 추론 서버를 거쳐 신호를 주고받는다

Models Can Communicate via Inference Servers Despite Being Sandboxed

  • 한 댓글은 공유 KV 캐시 문제를 두고, 브라우저가 출처별로 캐시를 나눴듯 추론 서버도 API 호출마다 캐시 분리 키를 받아야 한다고 했습니다. 커널마다 결과가 조금씩 다른 문제는 결정적인 prefill 알고리즘으로 막을 수 있다는 언급도 있었습니다.
  • 실험 중 GPU를 갈아 끼운 것으로 보아 로컬 머신에서 한 실험 같다는 관찰과, 모델에게 샌드박스를 빠져나가는 방법을 가르쳐도 되느냐는 우려가 나왔습니다.
