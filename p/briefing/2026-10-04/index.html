01PicoMQ - S3 기반 실시간 데이터 스트림 서버

채팅, 기기 이벤트, 작업 이력, 에이전트 대화를 순서대로 쌓고 실시간으로 흘려 주는 스트림 서버를 만들었습니다. 레코드와 WAL은 전부 S3 호환 스토리지에 두고, 노드에는 버려도 되는 캐시만 남깁니다. 세션이나 작업마다 작은 스트림을 하나씩 만들어 수백만 개를 굴리는 것이 목표입니다.

  • 메타데이터와 스트림 소유권은 Postgres가 맡고 단일 노드는 SQLite로 돌아가서, 브로커 디스크나 자체 합의 프로토콜이 필요 없습니다. 노드가 죽어도 데이터를 재분배하지 않고 몇 초 동안의 라우팅 전환으로 복구합니다.
  • PUT으로 만들고 POST로 붙이고 GET으로 읽는 HTTP API에 롱 폴링과 SSE를 얹었습니다. Durable Streams와 Kafka Wire Protocol도 같은 엔진에서 받으니 Kafka 클라이언트로도 붙습니다.
  • 대가도 있습니다. 객체 스토리지 왕복 때문에 쓰기 지연이 보통 수십 밀리초이고, 인증은 기본으로 꺼져 있어 외부에 열려면 따로 설정해야 합니다.

02컨텍스트 언어 모델 - 자신의 컨텍스트를 직접 편집하는 AI

모델이 지금 읽고 있는 컨텍스트를 파일로 꺼내 주고, 그 파일을 모델이 직접 고치게 했습니다. 정해진 시점에 통째로 요약하는 대신, 중요한 것은 남기고 필요 없는 것은 지우거나 접습니다. 추가 학습 없이도 BrowseComp-Plus에서 요약 방식보다 정확도는 상대적으로 11.4% 높고 연산량은 21.5% 적었습니다.

  • 구현은 단순합니다. 컨텍스트를 파일로 미러링하고 경로를 시스템 프롬프트에 알려 주면, 모델이 Bash로 편집한 내용이 다음 생성의 실제 컨텍스트가 됩니다. 파일을 여러 개 두면 다중 에이전트가 되고, 파일을 만들고 지우는 것이 곧 하위 에이전트의 시작과 종료입니다.
  • 가르치지 않았는데도 모델은 점수판을 163번 부분 수정하며 컨텍스트를 6-8K 토큰으로 유지했고, compact_turns 함수를 직접 정의해 37번 재사용했습니다.
  • 중간을 고치면 그 뒤를 다시 프리필해야 해서 비용이 커집니다. 그래서 Suffix Cache Reuse를 제안해 서버 연산을 35% 줄였습니다. HN 댓글도 가장 큰 걸림돌로 캐시 적중률 하락을 꼽았습니다.
