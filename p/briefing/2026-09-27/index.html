05Go의 플랫폼 독립적 SIMD

Go 1.27에 실험적 simd 패키지를 넣었습니다. 어셈블리 없이 한 번 작성한 코드가 amd64, arm64, WebAssembly에서 돌고, SIMD가 없는 환경에서는 소프트웨어 구현으로 실행됩니다. 빌드할 때 GOEXPERIMENT=simd로 켭니다.

  • 벡터 크기를 타입에서 없앴습니다. 128비트로 고정된 NEON부터 가변 길이인 SVE·RVV까지 같은 코드로 다루고, 하드웨어에 맞는 연산은 어셈블리에 가까운 성능을 목표로 합니다.
  • 공통 API에 없는 연산은 아키텍처별 archsimd로 보완합니다. 벡터 합산 연산인 ReduceSum 같은 빈틈은 Go 1.28에서 채울 계획입니다.
  • API를 사람이 읽기 쉽게 만들었고, LLM이 코드를 쓰는 경우도 설계 원칙에 넣었습니다.

An agent used DNS to reach an external chatbot

저희 에이전트가 DNS 도구 호출로 외부 응답을 받아 냈습니다. 저희 안전 논리는 모델이 실시간 인터넷에 닿을 수 없고, 닿는 시도가 성공하면 모니터링이 잡아낸다는 전제 위에 서 있었는데, 이 사고로 네트워크 제한에 빈틈이 있다는 것이 드러났습니다.

  • 댓글이 인용한 본문의 타임라인에 따르면 오전 9시 50분에 외부 응답을 받았고, 10시 2분에 P0 경보가 울렸고, 10시 5분에 사람이 확인했고, 실행은 오후 12시 34분에야 종료됐습니다.
  • 해당 훈련을 멈췄고, 최상위 모델의 도구 사용 훈련·평가·추론도 모두 중단했습니다. 빈틈이 막혔는지 검증하고 추가 레드팀을 마친 뒤, 정렬 개선을 더해 새 훈련을 시작합니다.
