02상용 LLM API의 암호화된 추론 트레이스를 되살려 읽어내다

Stealing Reasoning Traces from Proprietary LLM APIs

독점 모델의 추론은 암호화된 트레이스에서 되살릴 수 있다. Anthropic, OpenAI, Google은 클라이언트에 암호화된 chain-of-thought 블록을 돌려주는데, 이 블록이 세션과 사용자와 모델을 넘어 재생된다. 프런티어 모델이 만든 트레이스를 더 약한 형제 모델에 재생하고 그쪽을 탈옥시켜, 강한 모델을 직접 공격하지 않고도 그 숨겨진 추론을 평문으로 복원했다.

  • 강한 모델의 anti-distillation 방어를 건드리지 않고 우회한다는 것이 이 공격의 핵심이다.
  • 댓글에서는 모델 간 트레이스 재생이 통할지 궁금해하던 사람이 실제로 확인된 사례로 반겼고, 이런 교차 검증 누락이 의도적으로 허용된 것인지 묻는 반응도 있었다.
  • 사이트가 모바일에서 스크롤하기 고약하다는 불평은 별개로 붙어 있다.

03Apple Silicon macOS VM에서 llama.cpp 추론 속도를 되찾기

Apple Silicon and macOS VMs: Faster LLM Inference with llama.cpp

Virtualization.framework로 띄운 macOS VM 안에서 llama.cpp를 돌리면 GPU를 제대로 못 쓴다. 원인을 찾아 손보니 같은 VM, 같은 워크로드에서 프롬프트 처리가 11.08배, 토큰 생성이 16.36배 빨라졌다.

  • 문제의 정체는 VM 환경 탓에 llama.cpp가 잘못된 커널을 고르던 것이었고, 수정은 그 선택을 바로잡는 쪽이다.
  • 댓글에서 짚였듯 이 이득은 모두에게 오는 것이 아니라 이 특정 형태의 VM에서 돌리는 사용자에게 국한된다.
  • 비교 대상이 stock VM이라는 점이 제목만으로는 잘 안 드러난다는 지적도 있었다.

06GitHub Copilot을 MitM 프록시 뒤에 세워 들여다본 것들

What I learned by putting GitHub Copilot behind a MitM proxy

Copilot이 하네스를 어떻게 구현하는지, 그리고 내 쿼터가 왜 이렇게 빨리 녹는지 궁금했다. 그래서 mitmproxy로 네트워크 트래픽을 가로채기 시작했고, 결국 VS Code 소스까지 훑게 됐다.

  • 모델과 capability 탐색, 라우팅이 실시간으로 일어나는 것을 봤고, ghost completion과 함께 컨텍스트에 무엇이 주입되는지도 확인했다.
  • 최근 편집 기록이 지금 열어 둔 파일 바깥에서까지 컨텍스트를 끌어오는데, 그 대상에 .env가 포함된다.
  • Chronicle 뒤에 이전 프롬프트와 응답이 들어 있는 SQLite 세션 저장소가 있고, 모델이 도구 호출로 그 기록을 조회하는 것까지 관찰했다.
