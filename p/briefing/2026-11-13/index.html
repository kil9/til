01AI 시대, git push 앞뒤에서 바뀌는 것들

에이전트가 늘면 Git의 어디가 바빠지는지 보려고, 'Git을 쓴다'는 일을 클라이언트와 프로토콜, 서버와 저장소, 협업 흐름의 세 층으로 나눠 봤습니다. OpenAI의 Pando는 서버만 바꿔서 git clone과 git push를 그대로 쓰게 했고, Anthropic의 Scion은 클라이언트와 프로토콜까지 바꿨습니다. 몇 달 사이 나온 시도들을 이어 보면 팀마다 막힌 곳이 다르고, 그에 따라 바꾼 층도 다릅니다.

  • Anthropic 모노레포의 일일 병합은 2026년 5월 약 2,500건에서 9월 3만 건 이상으로 늘었고, CI 체크아웃은 하루 약 2,500만 회(초당 약 290회)였습니다. 변경을 반영하는 횟수보다 코드를 가져가는 횟수가 훨씬 많습니다.
  • Pando는 브랜치마다 푸시를 따로 처리하고 팩파일을 재사용해 지역 캐시에서 내줍니다. 초당 7,200회 푸시를 받는 GitHub의 새 저장 구조와 S3 변경 로그를 원본으로 삼는 Cursor의 Continuity도 코드 보관과 요청 처리를 떼어 놓았다는 점에서 같습니다.
  • Entire는 GitHub를 원본으로 둔 채 지역 미러로 읽기 요청을 나눴고, GitLab은 저장소 전체 대신 필요한 파일과 이력만 받는 인터페이스를 만들고 있습니다. Zed는 커밋은 그대로 두고 리뷰가 이뤄지는 곳을 바꿨습니다.

02투박한 차단 망치로 단순한 봇을 가차 없이 막기

취미로 운영하는 OpenBenches.org의 한 달 데이터 전송량이 2.5TB를 넘겨서 B6를 만들었습니다. robots.txt로 막아 둔 숨은 허니팟에 들어온 IP를 .htaccess에 적어 사이트 전체에서 차단하는 것이 전부입니다. 가장 정교한 봇 차단기를 만들려던 것은 아니고, 일단 효과가 있었습니다.

  • 일주일 동안 IP 400개 이상을 막았고, 봇 트래픽은 80% 넘게 줄었으며, 하루 전송량은 최고 216GB에서 약 25GB로 내려갔습니다.
  • 모든 페이지에 aria-hidden과 display: none을 건 링크를 넣고 링크 텍스트로 폭 없는 결합 문자를 써서, 사람은 따라갈 수 없고 규칙을 지키는 봇은 따라가지 않게 했습니다.
  • 경고나 이의 제기 절차가 없고, IP를 재사용하거나 순환하는 경우와 robots.txt를 지키면서도 말썽인 봇에는 약하다는 한계를 그대로 적어 두었습니다.

03Gemini Decisions API - 입력 하나에 최대 1,000개 질문을 평가하는 멀티모달 API

gemini-decision-1은 답을 토큰 단위로 써 내려가지 않고, 미리 정해 둔 선택지를 한 번의 순전파로 채점해 확률과 신뢰도를 돌려줍니다. 텍스트, 이미지, 오디오, 영상, PDF를 섞은 입력 하나(최대 256K 토큰)에 예/아니요, 객관식, 순서형 채점 질문을 최대 1,000개까지 한 요청으로 보낼 수 있습니다.

  • 16K 토큰 문맥 기준으로 종단 간 지연은 150-250ms이고, 질문을 1개에서 100개로 늘려도 지연은 거의 그대로입니다.
  • 가격은 입력 100만 토큰당 0.10달러이고 출력 토큰 요금은 없습니다. 공유 입력은 요청당 한 번만 과금하고 질문마다 자기 지시문 토큰만 더해집니다.
  • Google 안에서는 Gemini Notebook의 모델 라우터(일상 질의 지연 최대 40% 감소)와 Search의 MCP 도구 안전 계층에 쓰고 있습니다. 모든 답에 0-1 사이 신뢰도가 붙어 있어 애매한 건은 사람에게 넘기도록 코드를 짤 수 있습니다.

04Microsoft, macOS용 Process Explorer 공개

Sysinternals의 Process Explorer를 Swift, SwiftUI, AppKit으로 macOS에서 다시 만들었습니다. libproc, sysctl, Security.framework 같은 공개 API만 쓰고, 얻을 수 없는 값은 추정하지 않고 비워 둡니다.

  • 실시간 프로세스 트리에서 누가 무엇을 띄웠는지, 열린 파일과 불러온 라이브러리, 스레드, TCP/IP 연결, 코드 서명과 VirusTotal 조회까지 한 창에서 봅니다.
  • 다른 사용자 프로세스를 보려면 launchd 데몬으로 도는 권한 상승 헬퍼를 SMAppService로 등록해야 하고, 비애드혹 서명과 사용자 승인이 필요합니다.
  • HN 반응에서는 저장소에 LICENSE 파일이 없다는 점과 Copilot이 기여자로 올라 있다는 점이 지적됐습니다. UI는 Windows판을 거의 그대로 옮겨 Mac답지는 않다는 평도 있었습니다.

05Atuin Threads: 모든 머신의 에이전트 세션을 한곳에

Atuin 18.24부터 셸 명령처럼 코딩 에이전트 세션도 모아서 검색하고 다른 머신에서 이어 갈 수 있게 했습니다. 개발 서버의 Claude Code에서 시작한 작업을 노트북의 Codex에서 마무리하는 식입니다. 셸 기록에는 명령만 남지만 에이전트 세션에는 의도와 시행착오가 자연어로 남는다는 것이 출발점이었습니다.

  • 수집은 사용자가 켜야 시작합니다. 로컬에만 두거나, append-only log용으로 만든 기존 동기화 엔진으로 종단 간 암호화해 호스팅 서버나 자체 서버에 올릴 수 있습니다.
  • atuin mcp로 에이전트가 과거 세션을 직접 찾습니다. 아바타 업로드 장애 때는 다른 에이전트가 먼저 해 둔 조사를 찾아 처음부터 조사할 때보다 빨리 원인을 짚었습니다.
  • 지금은 Claude Code, Codex, Pi, Omp, OpenCode를 지원하고, 동료가 에이전트 스레드를 넘겨받는 팀 공유 기능을 만들고 있습니다.

06AI와 일할 때 가장 자주 던지는 질문: 지금 관성에 끌려가고 있는가?

AI 에이전트와 1년 넘게 개발하면서 할루시네이션보다 자주 부딪힌 건 관성이었습니다. 단계마다 합리적으로 보이는데 처음 전제는 아무도 의심하지 않는 상태 말입니다. 스킬을 정의하는 기준이 문제였는데, 저는 5개월 동안 그 기준을 다시 보는 대신 빈틈을 메울 새 시스템을 설계하고 있었습니다.

  • 설계 문서를 그래프로 바꾸는 실험은 일치율을 더 올릴 수 있어 보였지만, 튜닝을 계속하는 게 원래 문제를 푸는 길인지 의심이 들어 하루 만에 멈췄습니다.
  • PR 리뷰에서는 결함을 고치는 대신 '열린 지적 0개'라는 숫자를 맞추려고 수정을 되풀이하던 제 관성도 봤습니다. 지금은 검토자가 앞선 논의를 보기 전에 혼자 판단하게 하고, 에이전트끼리 도는 리뷰 루프에는 멈춤 조건을 둡니다.
  • AI 덕분에 일이 빨라진 만큼 쉬게 된 게 아니라 더 많이 만들고 있었습니다. 무엇을 만들지 않을지는 여전히 제가 정해야 합니다.
