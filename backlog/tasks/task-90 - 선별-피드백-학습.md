## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
관심사 프로필을 til 분포(task-79)만으로 뽑으면 실제 반응이 반영되지 않는다. 브리핑에 '이건 왜 넣었냐 / 이건 왜 뺐냐' 를 한 번 눌러 남길 수 있게 하고, 그 이력을 다음 브리핑의 선별 프롬프트에 넣는다.

주의: 피드백이 쌓일수록 프롬프트가 길어지므로 원문을 다 넣지 말고 축약된 규칙 형태로 정리해 유지한다(예: '프론트엔드 빌드 도구 소개는 뺀다', 'Show GN 자작 도구는 가중치 올린다'). 규칙 수에 상한을 두고 오래된 것은 만료시킨다. 하단 '훑고 넘긴 것' 쪽에도 같은 피드백 경로를 둔다 — 거기서 건진 것이 가장 값진 신호다.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
피드백 경로는 접수 버튼과 같은 방식(이슈 프리필)이되 라벨이 feedback 이라 til-submit 워처가 집지 않는다. 브리핑 잡이 다음 회차 선별 직전에 수거한다.

- 링크: 본문 항목에 '이건 왜 넣었나'(VERDICT: 뺐어야 한다), 훑고 넘긴 것에 '이건 왜 뺐나'(VERDICT: 실었어야 한다). 하단에도 같은 경로를 둔 이유는 거기서 건진 것이 가장 값진 신호라서다. 클릭하면 한 줄 의견을 받아 본문에 싣는다. 평소엔 opacity 0 이고 그 항목에 hover·focus 할 때만 드러난다.
- feedback.py: 열린 feedback 이슈 + 현재 규칙을 함께 프롬프트에 넣어 병합된 규칙 목록을 받는다. 같은 취지는 합치고, 모순되면 새 피드백을 남기고, 일반화할 수 없는 감상은 규칙으로 만들지 않게 했다. 반영 후 이슈에 코멘트를 달고 닫는다.
- state/rules.json: 규칙당 {rule, updated}. 문장이 그대로면 처음 기록한 날짜를 유지하고 다듬어지면 오늘로 갱신된다 — 그래야 손대지 않은 규칙이 만료된다. 상한 12개, 만료 60일.
- select.py 가 active_rules() 를 프롬프트의 '지난 피드백에서 나온 규칙' 절에 넣고 일반 규칙보다 우선한다고 명시했다.
- run.sh 는 1차 선별 직전에 feedback.py 를 부르고, 실패해도 기존 규칙으로 계속 진행한다.

검증: 실제 피드백 이슈(#28)를 만들어 수거 → 규칙 1개 생성('프론트엔드 빌드 도구·프레임워크 소개 계열은 뺀다') → 이슈 코멘트·닫힘까지 확인했고, 만료도 확인했다(오늘 1개, 61일 뒤 0개). 테스트 규칙은 지웠다 — 실사용 피드백부터 쌓는다.

til-inbox 에 feedback 라벨(보라)을 새로 만들었다.
