# 리브의 아침 브리핑 — 페이지 템플릿과 노출 정책 (task-81)

파일럿(`drafts/daily-report-pilot.html`, 비커밋 v5)을 정리한 결과물이다. 발행 잡(task-85)이
이 템플릿에 값을 채워 페이지를 만든다.

## 파일

| 파일 | 쓰임 |
| --- | --- |
| `template.html` | 페이지 셸(head·CSS·머리말·footer·액션 JS) |
| `item.html` | 선별 항목 하나(좌 본문 + 우 메타·액션) |
| `item-rest.html` | 하단 '훑고 넘긴 것' 그리드 한 칸 |

치환은 `{{NAME}}` 토큰이다. 값은 HTML escape 한 뒤 넣는다(제목·요약에 `&`·`<` 가 섞여 온다).
`button` 의 `data-*` 속성에 들어가는 값은 큰따옴표 escape 까지 확인한다.

### `template.html` 토큰

| 토큰 | 값 |
| --- | --- |
| `{{DATE}}` | `YYYY-MM-DD` (canonical·OG·요청 본문 SOURCE 에 함께 쓰인다) |
| `{{DATE_KO}}` | `2026-07-26 (일)` |
| `{{DESCRIPTION}}` | 한 줄 설명(meta·OG 공용) |
| `{{FAVICON_B64}}` | 리브 원형 파비콘 base64 (루트 `index.html` 의 것을 그대로) |
| `{{ROOT_REL}}` | 사이트 루트 상대경로. `p/briefing/` 은 `../../`, `p/briefing/<날짜>/` 는 `../../../` |
| `{{ARCHIVE_REL}}` | 아카이브 상대경로(task-87). 그전까지는 `{{ROOT_REL}}p/briefing/` |
| `{{SCANNED}}` / `{{PICKED}}` | 훑은 건수 / 선별 건수 |
| `{{INTRO}}` | 리브 머리말. `<p>` 여러 개, 첫 문단에 `.sticker-hero` 스티커 하나 |
| `{{PICK_ANCHOR}}` / `{{PICK_LINE}}` | 강추 1건의 앵커(`i05` 등)와 왜 권하는지 한 줄 |
| `{{TOC_ITEMS}}` | `<li><a href="#i01">…</a></li>` 목록. 순서는 본문과 같다 |
| `{{DAYNAV}}` | 이전/다음 회차 이동 내비(task-92). `<!-- DAYNAV:START -->`\~`END` 마커 안에 들어간다 |
| `{{ITEMS}}` | `item.html` 을 이어 붙인 것 |
| `{{REST_ITEMS}}` | `item-rest.html` 을 이어 붙인 것 |

### `item.html` 토큰

`{{ANCHOR}}`(`i01`…), `{{RANK}}`(`01`…), `{{URL}}`(GeekNews 토픽 링크), `{{TITLE}}`,
`{{LEDE}}`, `{{BULLETS}}`(`<li>` 2-3개), `{{DOMAIN}}`(원문 도메인),
`{{INTEREST}}`(`관심사 최상`/`상`/`중`/`밖` 등), `{{PERCENTILE}}`(추천 백분위 상위 N%),
`{{ACTION_TOPIC}}`·`{{ACTION_URL}}`·`{{ACTION_ANGLE}}`(til 요청 본문 재료).

`{{TIEBOX}}` 와 `{{LIV}}` 는 있을 때만 채우고 없으면 빈 문자열이다.

```html
<div class="tiebox"><span class="lbl">til 연관</span><a href="{{ROOT_REL}}2026/<slug>/">글 제목</a> 이 …</div>
<div class="liv"><img src="data:image/webp;base64,…" alt="리브" width="72" height="72"><p>한마디</p></div>
```

## 레이아웃 원칙 (파일럿 평가에서 확정)

- 폭은 1160px 2칼럼. til 본문 페이지(720px)보다 넓다. 900px 이하에서 1칼럼으로 접힌다.
- 위에서 아래로 한 번만 읽힌다. 항목마다 좌(본문) + 우(til 연관·리브 한마디·액션)로 완결하고,
  되돌아가서 읽어야 하는 요소를 만들지 않는다.
- 최상단 우측은 오늘의 개요(강추 1건 + 전체 미니 목차, 본문 앵커).
- 선별 제외분은 접지 않고 맨 아래 3열 그리드에 한 줄 요약으로 전부 노출한다.
- til 정합성은 고정 섹션이 아니라 `.tiebox` 하나로 녹인다. 연관이 약하면 생략한다.
- 항목 요약은 '~라는 글이다' 식 3인칭 설명이 아니라 저자가 직접 말하는 어투로 쓴다.
- 매일 같은 정보(선정 기준·관심사 프로필·수집 범위)는 싣지 않는다. 상설 소개
  페이지(`p/liv-briefing/`, task-84)로 빼고 footer 한 줄로 링크한다.
- 임베드 자산은 hero 스티커 1개 + 아바타 4개까지(약 29KB). 페이지 전체는 90KB 안팎이고
  상한은 100KB 다 — 실측해 보니 용량을 정하는 것은 자산이 아니라 본문이었다(57KB).
  자산만 줄여서는 40KB 로 못 내려가고, 내리려면 실을 항목 수를 줄여야 한다.

## 경로·노출 정책

- `p/briefing/` 이 항상 최신 1건, `p/briefing/<YYYY-MM-DD>/` 로 과거분이 누적된다.
  최신판과 날짜판은 같은 내용이고 상대경로 깊이만 다르다(`{{ROOT_REL}}`, 내비는 `{{DAYNAV}}`).
- 회차 사이 이동은 페이지 하단의 하루 단위 내비다(task-92). 발행 시점에 정적으로 박으며,
  새 회차가 나오면 `repatch_daynav()` 가 직전 회차 페이지의 마커 구간만 갈아끼워 '다음'
  링크를 채운다. 그래서 발행 커밋에는 오늘 것 외에 어제 페이지 1개가 함께 들어간다
  (`run.sh` 가 `p/briefing` 을 통째로 add 하는 이유).
- 루트 갤러리 카드·README 표·`p/archive/` 에는 넣지 않는다. 매일 1건이 카드로 쏟아지면
  til 본문 글이 묻힌다. 진입은 루트 사이드바의 '오늘의 브리핑' 링크 한 줄과
  `p/briefing/archive/`(task-87) 두 곳이다. 사이드바에서 그 블록은 '리브의 코멘트'
  아래(월별 목차 위)에 둔다 — 사이드바 위쪽은 소개·코멘트 자리다(task-92).
- 검색엔진에는 `noindex, follow` 로 내보낸다. 브리핑이 til 본문 글보다 많이 잡히면
  사이트의 얼굴이 바뀐다. 링크는 따라가게 두어 원문·til 글로 가는 경로는 살린다.
- 날짜판은 무기한 누적한다. 페이지 90KB × 365 = 연 33MB 수준으로, Pages 한도(1GB)에는
  한참 못 미친다. 저장소 클론이 무거워진다고 느껴지면 그때 보존 기간을 다시 본다.
- `404.html` 리다이렉트 맵에는 등록하지 않는다. 구 평면 URL 시절에 없던 경로다.

## 읽음/안읽음 (task-93)

독자가 사실상 관리자 한 명이라 서버 상태·인증 없이 브라우저 `localStorage` 에만 남긴다.
크롤러는 JS 를 돌리지도 저장하지도 않으므로 이 기록에 섞이지 않는다.

- 키는 `liv-briefing-read`, 값은 방문한 회차 날짜의 JSON 배열. 회차 페이지가 열리는 즉시 기록한다.
- 표시는 두 곳이다. 루트 사이드바 '오늘의 브리핑' 배지(`.briefing-new`, 최신 회차를 안 읽었을 때만)와
  `p/briefing/archive/` 목록의 행 구분(`.row.read` 흐리게 / `.row.unread` 점).
- 사이드바는 최신 회차 날짜를 `p/briefing/latest.json`(render.py 가 발행 때 쓴다)에서 읽는다.
  루트 `index.html` 에 날짜를 박지 않는 이유는 그 파일을 AI 요약 잡이 매일 따로 고쳐 쓰기 때문이다.
- 한계: 브라우저마다 따로 논다(폰에서 읽은 것이 데스크톱에 안 보인다). 저장소가 막힌 브라우저에서는
  표시만 빠지고 레이아웃은 그대로다 — 관련 JS 는 전부 `try`/`catch` 안에 있다.
