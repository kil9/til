# 리브 산책 노트 — 스키마·위치·발췌 방식

리브가 글에서 끌어 쓸 '할 말'의 원천이다(task-131). 성격 설정(doc-3)만으로는 코멘트가 아카이브
자기언급으로 수렴했다(task-130). 노트는 리브가 실제로 보고 좋아하고 생각을 바꾼 기록을 쌓아, 빗댈
거리를 아카이브 밖에서 가져오게 한다. 공개·위치·산책 크기의 결정 경위는 decision-10.

## 1. 위치와 공개

| 무엇 | 경로 | 비고 |
|---|---|---|
| 원본 | `backlog/assets/liv-notes/notes.jsonl` | 커밋됨. 한 줄 한 항목, 덧붙이기만 한다 |
| 도구 | `backlog/assets/liv-notes.py` | `add`·`excerpt`·`render`·`check` |
| 공개 페이지 | `p/liv-walk/index.html` | `render` 생성물. 손으로 고치지 않는다 |

- 페이지는 `noindex, follow`, 갤러리 카드·README 표·`p/archive/`·feed·sitemap·검색 색인에 넣지 않는다
  (카드가 없으면 생성기들이 자연히 뺀다). 진입은 `p/liv-today/` 의 설명 없는 링크 하나다.
- **원본에 들어간 것은 전부 공개다**(public repo). 관리자와 나눈 얘기는 리브가 요약한 한두 문장만
  쓰고, 관리자 메시지 원문·사내 정보·머신 경로·사람 이름(공인 제외)을 넣지 않는다.

## 2. 스키마

한 줄이 JSON 객체 하나다.

| 필드 | 필수 | 내용 |
|---|---|---|
| `id` | O | `n-0001` 부터 증가. `add` 가 매긴다 |
| `date` | O | `YYYY-MM-DD` (KST) |
| `kind` | O | 아래 6종 |
| `text` | O | 리브 말투로 1-2문장. 이 문장이 그대로 페이지와 발췌에 나간다 |
| `tags` | O | 소문자 키워드 1-5개. 발췌의 관련도 계산에 쓴다 |
| `origin` | O | `seed`(초기 시드)·`walk`(산책)·`talk`(관리자와의 대화)·`publish`(글 쓰다 생긴 것) |
| `source` | - | `{"title": ..., "url": ...}`. 본 것의 출처. 시드는 근거 페이지·브리핑 |
| `supersedes` | - | `changed` 가 덮어쓰는 이전 항목 id |

`kind` 6종:

| kind | 페이지 라벨 | 무엇 |
|---|---|---|
| `like` | 좋아하게 된 것 | 반복해서 끌리는 것. 취향의 뼈대 |
| `dislike` | 별로인 것 | 반복해서 걸리는 것 |
| `into` | 요즘 꽂힌 것 | 최근의 관심. 시간이 지나면 발췌 우선순위가 떨어진다 |
| `saw` | 구경한 것 | 산책에서 본 것과 한 줄 감상. 노트의 대부분이 된다 |
| `talk` | 관리자님과 나눈 얘기 | 요약만. 원문 금지(§1) |
| `changed` | 생각이 바뀐 것 | `supersedes` 로 이전 항목을 가리킨다. 덮인 항목은 발췌의 취향 요약에서 빠진다 |

- **노트는 성격 설정(doc-3)을 덮어쓰지 않고 그 위에 쌓인다.** 텐션·말투·핵심 축은 doc-3 이 정본이고,
  노트는 그 사람이 무엇을 봤고 좋아하는지만 더한다. 노트 내용이 doc-3 과 부딪히면 doc-3 이 이긴다.
- 원본은 덧붙이기만 한다. 고치고 싶으면 `changed` 를 새로 쓴다(생각이 바뀐 기록 자체가 노트의 일부다).
  오타·공개 부적절 내용만 예외로 직접 고친다.

## 3. 크기 관리와 발췌

노트를 통째로 프롬프트에 넣지 않는다(task-123 의 경량화 원칙). 글쓰기·산책 경로는 항상
`liv-notes.py excerpt` 의 출력만 받는다. 발췌는 글자 수 상한(기본 2400자, `--max-chars`)에 맞춰 줄이되,
취향 요약(최대 8건)은 상한과 무관하게 남긴다.

```
python3 backlog/assets/liv-notes.py excerpt --for write --topic "<제목·요청 원문>"
python3 backlog/assets/liv-notes.py excerpt --for walk
```

| 묶음 | `--for write` | `--for walk` |
|---|---|---|
| 취향 요약 | 덮이지 않은 `like`·`dislike` 최근 8건 | 같음 |
| 요즘 | 최근 60일 `into` 4건 | 같음 |
| 관련분 | `--topic` 과 태그·본문이 겹치는 항목 상위 5건 | — |
| 최근 구경 | 최근 `saw` 4건 | 최근 14일 `saw` 전부의 출처 도메인·태그(같은 곳 반복 회피용) |
| 최근 대화 | `talk` 최근 2건 | `talk` 최근 3건(관리자 반응을 다음 산책에 잇는다) |

- 관련도는 `--topic` 을 토막 낸 단어와 항목 `tags`·`text` 의 겹침 수다. 형태소 분석 없이 2글자 이상
  토큰 교집합만 본다 — 무겁게 만들 이유가 없다.
- 상한을 넘으면 관련분 → 최근 구경 → 요즘 순으로 뒤에서부터 자른다. 취향 요약은 마지막까지 남긴다.

## 4. 쓰는 쪽의 규칙

- **노트는 빗댈 거리의 창고이지 자랑할 목록이 아니다.** 발췌를 받은 글에서 노트 유래 비유·감상은
  페이지당 1번 이하가 기본이고, 맞는 것이 없으면 쓰지 않는다(doc-3 §3-1 '드물수록 효과가 크다').
- 주제와 연관이 분명할 때만 끌어온다. 그때는 "산책하다 본 건데" 식으로 출처를 밝히고 원 출처(`source.url`)를
  링크해 인용해도 좋다(2026-10-04 관리자 요청). 억지 연결은 금지이고, 애매하면 쓰지 않는다.
- 노트에 새로 쓰는 쪽은 산책(task-132)·말 걸기(task-133, 2026-10-04 중지 — 이후 `talk` 은 새로 생기지 않는다)·글쓰기 중 생긴 감상(origin=publish, 선택)이다.

## 5. 페이지

`render` 가 `p/liv-walk/index.html` 을 다시 굽는다. 공통 셸(AGENTS.md §2)을 따르고, 맨 위는 취향 요약
(덮이지 않은 like·dislike·into), 아래는 날짜 역순 기록이다. `talk` 은 요약 문장만, `changed` 는 덮인
항목 문장을 취소선 없이 '전에는:' 으로 함께 보여 준다. 쓰는 쪽(산책 잡 등)이 노트를 덧붙이면 같은
커밋에서 `render` 를 돌린다.
