## Implementation Notes

nuc14 walk.py(백업 state/walk.py.bak-redesign): usage_tier 가 리셋까지 남은 시간·사용률을 함께 넘기고 redesign_day 가 개편 날을 고른다 — 리셋 24시간 안쪽 + 주간 60%·5시간 50% 미만 + 최근 6일 안 개편 없음. 리셋 직전 회차를 놓친 주를 위해 개편이 9일 넘게 없으면 여유만 보고 연다(이력이 아예 없을 땐 이 대체 조건을 쓰지 않는다). 개편 날은 예산 +$8·호출 +20·시간 +20분, 프롬프트의 '페이지 다듬기' 절이 DESIGN_REDESIGN(전면 개편 허락, 흉내 금지·390/1280px·다크 모드 조건 유지)으로 바뀐다. CSS 상한은 개편 날만 늘리지 않고 16000자로 하나로 올렸다 — 개편으로 길어진 CSS 를 다음 날 조금씩 고칠 때도 통과해야 해서다. redesign 표시는 모델이 아니라 코드가 붙이고 기록에 '개편' 꼬리표로 보인다. 검증: 조건 4종 단위 확인, apply-walk 로 개편 기록 반영과 검증 실패 시 전날 CSS 유지 확인. 실제 첫 개편은 2026-10-25 04:30 회차가 될 가능성이 높다(10-24 기준 주 경과 78%).
